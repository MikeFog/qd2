# Типы роликов (`iRollerActionType`) — инвентаризация

Состояние на 03.10.2026, master `67f2316`. Только чтение кода и базы, ничего не менялось.
Краткое описание для заказчика — `docs/roller-types-customer.md`.

**Соглашение об именах.** Типы всегда называются так, как в таблице раздела 1, —
«Название» (ID). Групповых слов («промо», «идентификаторы СМИ», «обвязка», «агитация», «простой
ролик», «семейство агитации») в тексте нет: если правило касается нескольких типов, они
перечислены поимённо. Исключение — дословные цитаты сообщений и имён из базы и кода; к ним
рядом указано, какие типы имеются в виду.

Не путать: **тип ролика** (`Roller.rolActionTypeID` → `iRollerActionType`, это документ) ≠
**предмет рекламы** (`AdvertType`) ≠ **вид вещания** (`rolTypeID` / `RolType`, радио/ТВ). Тип
хранится только у ролика; выпуск (`Issue`) своего типа не имеет, процедуры берут его через
`Issue.rollerID → Roller`.

## 1. Справочник

`Roller.rolActionTypeID TINYINT NOT NULL DEFAULT 1`, FK `FK_Roller_RollerActionType`, индекс
`IX_Roller_rolActionTypeID` (нужен проверке `AgitationMixError`). В таблице нет ни одного
признака поведения — только `name`. Всё поведение зашито литералами в SQL и C# (раздел 9).

## 3. Карточка ролика

- Тип выбирается из выпадающего списка `rolActionTypeID` (паспорт сущности 20, источник
  `rolActionType`). Процедура `RollerPassport` отдаёт **все** строки `iRollerActionType` без
  фильтра — пользователь может выбрать и три типа, которые должна ставить система: «Отбивка
  политической агитации» (7), «Локальное СМИ (агитация)» (44), «Федеральное СМИ (агитация)» (55).
- Тип нельзя менять у ролика, уже стоящего в выпусках: десктоп отключает поле
  (`RollerPassportForm.cs:43`), веб — `RollerPassport.cs:39`, сервер — `RollerCannotChange`
  (`RollerIUD.sql:84–96`; проверяются только `Issue`, не модульные/пакетные выпуски).
- Имя ролика уникально **внутри типа** (`RollerName_Unique`, `RollerIUD.sql:31`): одно имя в
  разных типах допустимо.
- Ролик в прайс-листе модуля/пакета обязан быть типа «Новость» (2) или «Программа» (3)
  (+ `isCommon`, `isEnabled`), иначе `RollerCannotChangeWithPriceListPackAndModule`
  (`RollerIUD.sql:104,112`).
- Клонирование при смене предмета рекламы (`ActionRollerSetAdvertType`,
  `SetAdvertTypeForCommmonRoller`) тип копирует: клон «Агитационные материалы» (6) остаётся
  «Агитационные материалы» (6).
- Карточка радиостанции, вкладка «Политическая агитация»: три выпадающих списка, в каждом только
  ролики одного типа — «Локальное СМИ (агитация)» (44), «Отбивка политической агитации» (7),
  «Федеральное СМИ (агитация)» (55) (`massmediaPassport.sql:42–64`). На сервере (`MassmediaIUD`)
  соответствие типа не проверяется.

## 5. Автообрамление (`AgitationFraming`)

Режимы `InsertForWindow` / `InsertForAction` / `CleanupWindow`, `WITH EXECUTE AS OWNER`. Вокруг
подтверждённого выпуска «Агитационные материалы» (6) создаёт служебные выпуски «Локальное СМИ
(агитация)» (44) → «Отбивка политической агитации» (7) → «Федеральное СМИ (агитация)» (55), если в
карточке радиостанции выбраны ролики этих трёх типов.

- Служебная сущность: фирма «(Служебная) Обвязка политагитации» (имя фирмы в базе), её акция
  (`userID = 0`, бессрочная, подтверждена), кампания на станцию.
- «Локальное СМИ (агитация)» (44) — в первое окно цепочки (`windowPrevId`/`windowNextId`),
  «Федеральное СМИ (агитация)» (55) — в последнее, «Отбивка политической агитации» (7) — в окно с
  «Агитационные материалы» (6). Дубли не создаются; «Локальное СМИ» (4), поставленное человеком,
  вытесняет «Локальное СМИ (агитация)» (44), а «Федеральное СМИ» (5), поставленное человеком, —
  «Федеральное СМИ (агитация)» (55).
- Интервалы-исключения станции (`agitationExcludeIntervals`): в это время вставляется только
  «Отбивка политической агитации» (7).
- Пишет `Issue` напрямую, мимо `hlp_IssueVerify`: переполнение окна допускается намеренно.
- Снятие: `CleanupWindow` — если в цепочке не осталось подтверждённого выпуска «Агитационные
  материалы» (6), удаляет выпуски «Отбивка политической агитации» (7), «Локальное СМИ (агитация)»
  (44), «Федеральное СМИ (агитация)» (55) служебной акции прямым `DELETE`. «Локальное СМИ» (4) и
  «Федеральное СМИ» (5), поставленные человеком, не трогает.

Вызывается из: `ActionActivate:732`, `ActionDeactivate:154`, `ActionIUD:74`, `IssueIUD:290/323`,
`IssueTransfer:231/236`, `CampaignTransferDay:367/384`, `CampaignIUD:166`,
`CampaignsIssueDelete:186`. Из C#/Razor не вызывается.

- **Сетка вещания** (`rpt_Grid_v3`; десктоп — `GridReportCreator`, веб — `/broadcast-grid`
  и «Экспорт сеток вещания», Word `BroadcastGridDocx`):

  - ветка с DISTINCT — `= 2 OR (>= 3 AND NOT IN (6,8,9))` (стр. 534), то есть «Новость» (2),
    «Программа» (3), «Локальное СМИ» (4), «Федеральное СМИ» (5), «Отбивка политической агитации»
    (7), «Локальное СМИ (агитация)» (44), «Федеральное СМИ (агитация)» (55) и **любой новый тип по
    умолчанию**;
  - `rollerDurationSum` (занятое время в окне — число жирным под окном; слева в той же строке
    длительность окна) — только «Реклама» (1) (стр. 476, 520);
  - при отборе по менеджеру выпуски служебной акции (`userID = 0`) — «Отбивка политической
    агитации» (7), «Локальное СМИ (агитация)» (44), «Федеральное СМИ (агитация)» (55) — из сетки
    пропадают; в выгрузке для эфира отбора нет — они видны.
- **«Заполняемость» и «Фактическое время рекламы»** (`stat_FillPercentage`, две строки внизу
  сетки, за день по станции): «Фактическое время рекламы» (`realTime`) — сумма длительностей
  подтверждённых выпусков (`isConfirmed = 1`, макеты не считаются) с `rolActionTypeID IN (1,8,9)`,
  то есть «Реклама» (1), «Локальное промо со спонсором» (8), «Локальное промо без спонсора» (9), в
  четырёх копиях (стр. 150, 237, 321, 407); «Заполняемость» (`fill`) — то же время в процентах от
  суммы длительностей всех окон дня с тарифом (знаменатель от типов не зависит).
- **Без фильтра по типу** (считают все одиннадцать типов): `Grid`, `ActionRecalculate`,
  `Stat_VolumeOfRealizationSec`, `stat_VolumeOfRealizationNew`, `stat_RollerStatistic`,
  `ActionRollerStats`, `job_DeleteEmptyActions`. Служебные выпуски «Отбивка политической
  агитации» (7), «Локальное СМИ (агитация)» (44), «Федеральное СМИ (агитация)» (55) попадают в
  эти статистики наравне с остальными. Цена выпуска от типа не зависит (скрытый тип оплаты
  «промо» — отдельная история).
- Медиаплан по акциям и справки в эфир (`OnAirInquireReport`, `ExportMediaPlusFormat`) работают по
  одной кампании — служебные выпуски «Отбивка политической агитации» (7), «Локальное СМИ
  (агитация)» (44), «Федеральное СМИ (агитация)» (55) в них не попадают.

## 7. Выгрузка DJin подробно

Путь данных: `rpt_Grid_v3` (без менеджера) → `BroadcastGridExport.AdjustIssuePositions`
(раскладка позиций в окне) → `ExportDocument.ExportBlocks` (блоки, влёт/аут) →
`DJinExportDocument.PrintRoller` (строка ролика) → `BlockManager.Process` (перестановка типов).
Один код обслуживает десктоп и веб (`ExportToMemory`). До двух файлов на станцию: до полуночи и
после.

`AdjustIssuePositions` в каждом окне ставит «первый» и «второй» ролики, затем остальные так, чтобы
два ролика одного предмета рекламы (`advertTypeId`, подпредмет — не группа) не стояли рядом,
в том числе с «первым»/«вторым» и с «последним»: каждый раз берётся самый многочисленный предмет,
не совпадающий с предыдущим роликом (предмет «последнего» считается на один больше). Типы, которые
`BlockManager` выносит из середины блока (4, 5, 6, 7, 8, 9, 44, 55), в разведении не участвуют.
Соседство одного предмета остаётся, только когда его не избежать (один предмет занимает больше
половины окна). До 08.10.2026 закреплённые позиции и служебные строки не учитывались.

1. `ExportBlocks`: строка с типом NULL (пустое окно) ролик не пишет. В окне «прямого эфира»
   (`isAlive`) роликов и джинглов нет, для любого типа (`PrintRoller:52`).
2. `PrintRoller`: метка, громкость — таблица 2.3. Любой тип, не названный явно, выйдет как `c` с
   громкостью рекламы.
3. `GetFileName`: суффикс даты (`yyMMdd` + суффикс) добавляется ко всем типам, кроме
   «Реклама» (1), «Локальное СМИ» (4), «Федеральное СМИ» (5), «Агитационные материалы» (6),
   «Отбивка политической агитации» (7), «Локальное промо со спонсором» (8), «Локальное промо без
   спонсора» (9), «Локальное СМИ (агитация)» (44), «Федеральное СМИ (агитация)» (55) — то есть на
   практике к «Новость» (2) и «Программа» (3) (**и к любому новому типу**).
4. `BlockManager.ProcessBlock`: блок без единой строки между началом и концом блока выбрасывается;
   блок, в котором нет ни одного ролика из типов «Локальное СМИ» (4), «Федеральное СМИ» (5),
   «Агитационные материалы» (6), «Отбивка политической агитации» (7), «Локальное промо со
   спонсором» (8), «Локальное промо без спонсора» (9), «Локальное СМИ (агитация)» (44),
   «Федеральное СМИ (агитация)» (55), остаётся как есть. Иначе порядок в блоке такой:
   1. «Локальное СМИ» (4);
   2. «Локальное промо без спонсора» (9);
   3. влёт (In);
   4. «Локальное промо со спонсором» (8);
   5. «Реклама» (1), «Новость» (2), «Программа» (3) — в порядке сетки;
   6. «Локальное СМИ (агитация)» (44);
   7. «Отбивка политической агитации» (7);
   8. «Агитационные материалы» (6);
   9. «Федеральное СМИ (агитация)» (55);
   10. аут (Out) и музыкальная добивка;
   11. «Федеральное СМИ» (5).

   Метки типов 6, 7, 8, 9, 44, 55 в готовом файле заменяются на `c`; метки типов 4 и 5
   (`c-type-4`, `c-type-5`) остаются.
5. Нет влёта (тариф без `needInJingle`) — «Локальное промо со спонсором» (8) встаёт сразу за
   «Локальное промо без спонсора» (9) или первым. Несколько роликов одного типа 8 или 9 — в порядке
   сетки, ограничений по количеству нет.
6. В блоке нет рекламы — влёт и аут вычищаются. Рекламой считаются «Реклама» (1), «Новость» (2),
   «Программа» (3), «Агитационные материалы» (6), «Локальное промо со спонсором» (8). Не считаются
   рекламой «Локальное СМИ» (4), «Федеральное СМИ» (5), «Отбивка политической агитации» (7),
   «Локальное промо без спонсора» (9), «Локальное СМИ (агитация)» (44), «Федеральное СМИ
   (агитация)» (55) и музыкальная добивка.
7. Название блока: «Реклама в HH:mm», если **первый** ролик окна — «Реклама» (1), иначе —
   комментарий тарифа (`PrintBlockStart:134`, `type > 1 ? description : "Реклама"`). Тип берётся
   из порядка сетки, до перестановки `BlockManager`. Для окон, начинающихся с «Агитационные
   материалы» (6), «Локальное промо со спонсором» (8), «Локальное промо без спонсора» (9) или
   «Локальное СМИ (агитация)» (44), имя блока будет комментарием тарифа — по живому файлу не
   проверялось.

Не живой код: `VideoDJExportDocument`, `VectorBoxExportDocument` (формат `PLX`),
`DJinReaderDocument` (склейка файлов DJin), `ExportType.VectorBox/VideoDJ` — не входят в
`Client.csproj`; единственный формат — DJin (`ExportDocument.GetDocument`). `rpt_Grid` (legacy),
`rpt_Grid_v2` и `GridReportCreater.cs` (с опечаткой) удалены 06.10.2026 (`Deploy/20`).

## 10. Как добавить новый тип (чек-лист)

1. Строка в `iRollerActionType` (`IDENTITY_INSERT`, скрипт в `ArtvisDB/Scripts`).
2. Решить по каждому столбцу таблиц 2.1–2.3 и записать ответ в документ задачи.
3. DJin: `PrintRoller` (метка/громкость), `GetFileName` (суффикс даты), `BlockManager` (метка,
   порядок, нормализация, «считается рекламой»). Если `BlockManager` выносит новый тип из середины
   блока — добавить его в `BroadcastGridExport.TypesOutOfBlockBody`, иначе он будет участвовать в
   разведении предметов рекламы.
4. `rpt_Grid_v3`: ветка с DISTINCT или без; `rollerDurationSum`.
5. `stat_FillPercentage` — все четыре копии.
6. `hlp_IssueVerify` (позиция, «один в окне», ёмкость), `IssueTransfer`, `ActionActivate` (оба
   места `DisabledInsertSimpleRoller`).
7. Если новый тип должен вести себя как «Агитационные материалы» (6), «Отбивка политической
   агитации» (7), «Локальное СМИ (агитация)» (44) или «Федеральное СМИ (агитация)» (55) — все
   четыре `AgitationMixError` (+ `RollerSubstitute`).
8. Сообщения: `iMessage` (+ `es.tsv`), при необходимости `iMessageToActivate`/`iMessageToSubtitute`.
9. Деплой-скрипт: полные тексты затронутых процедур. Учесть, что в `local-promo-roller-types-deploy.sql`
   лежит устаревшая `hlp_IssueVerify` (без `PromoPositionForbidden`), а в `issue-price-from-db-deploy.sql`
   — `IssueIUD` без типа ролика в `UpdateItem`: актуальны файлы в `ArtvisDB/dbo/Stored Procedures` и
   `promo-position-forbidden-deploy.sql`.

## 11. Идея на обсуждение (не реализуется без решения)

Сейчас каждый тип — набор литералов в трёх десятках объектов (раздел 9). Вместо этого в `iRollerActionType` можно
завести признаки (`allowPosition`, `maxPerWindow`/`slotGroup`, `countInFill`, `countInGridSum`,
`isAdvertForDjin`, `djinMarker`, `djinOrder`, `isSystem`) и одну функцию-справочник; процедуры и
выгрузка читали бы признаки, а не `IN (1,8,9)`. Выгрузка DJin получала бы признаки из
`rpt_Grid_v3` одной колонкой. Цена — правка тех же объектов один раз и риск регрессии; польза —
новый тип становится строкой в таблице. Оценивать стоит после ответа заказчика по Н-1.
