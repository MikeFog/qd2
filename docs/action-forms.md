# Формы акции и кампании (десктоп) — справочник

Обследование 02.10.2026 (master `bada0be`). Предмет — то, как в десктопе **создаются** рекламные
акции и кампании и какими формами редактируется их размещение: карточка акции `ActionForm`,
«суперформа» кампании `CampaignForm`, веер `EditIssuesForm`, комбо-модули
`ComboModulePlacementForm`, мастера и диалоги вокруг них.

Проект веб-версии на основе этого обследования — [`docs/tasks/web-action-forms.md`](tasks/web-action-forms.md).

Связанные документы. Сетки, на которых стоят формы (иерархия, процедуры, замеры, П-1…П-17), —
[`docs/tariffgrid.md`](tariffgrid.md). Веер глазами пользователя — `docs/veer-editor-behavior.md`;
комбо-модули — `docs/tasks/combo-modules.md`; массовые операции по окнам —
`docs/mass-window-operations.md`; путь клика до процедуры — `docs/scenarios/*.md`.

Пометка «по чтению» означает, что вывод сделан по коду, а вживую не проверялся. Пути без
каталога: `CF` = `Client/Forms/CampaignForm.cs`, `EIF` = `Client/Forms/CreateActionMaster/EditIssuesForm.cs`,
`CMPF` = `Client/Forms/CreateActionMaster/ComboModulePlacementForm.cs`.

## 1. Карта форм

```
Создание (меню «Рекламный отдел»)
  Внести макет рекламной акции   фирма → ActionForm (акция ещё не записана)
  Веерное размещение…            фирма → SelectMassmediasStep → EditIssuesForm → ActionForm
  Размещение комбо-модулями…     фирма → SelectComboModuleStep → ComboModulePlacementForm → ActionForm¹

Редактирование (журнал акций, действие «Редактировать»)
  акция                          ActionForm
  кампания                       CampaignForm с сеткой по типу кампании
  часть спонсорской кампании     CampaignForm с сеткой роликов или программ

Кнопки ActionForm
  Добавить рекламную кампанию         CampaignNewForm
  Редактировать размещение роликов    CampaignForm (сетка по типу кампании)

  Веерное редактирование              EditIssuesForm
```

## 2. Как создаётся акция

### 2.1 Точки входа

| Путь | Когда пишется `Action` | Как пишутся кампании | Состояние | Куда попадает пользователь |
|---|---|---|---|---|
| **Внести макет** (`miCreateUnconfirmedAction`, `MDIForm.cs:490-505`) | лениво: при первом «Добавить кампанию» (`ActionForm.cs:154`) или первом клике в «Размещении модулями». Закрыли пустую карточку — в базе ничего | `CampaignNewForm` → `CampaignIUD` на каждую станцию, каждая в своей транзакции; пересчёта нет | макет | карточка |
| **Веерное размещение** (`miMasterCreateActions`, `MDIForm.cs:507-531`) | сразу по «ОК» шага станций | процедура `CreateActionWithRange`: прямой `INSERT INTO Campaign` **в обход `CampaignIUD`**, только линейные, не меньше двух станций | макет | веер, затем карточка — всегда, даже если ничего не поставили |
| **Размещение комбо-модулями** (`miComboModulePlacement`, `MDIForm.cs:538-561`) | лениво, по первому клику, в одной транзакции с выпуском | `CampaignIUD` (тип 3) на станцию модуля, тоже по первому клику | макет | карточка, только если акция появилась |
| Клонировать (меню акции в журнале) | `ActionIUD` | `CampaignIUD` + выпуски со сдвигом дат, пересчёт | всегда макет | журнал итогов |
| Разделить рекламную акцию / кампании | `ActionIUD` | перенос кампаний (`CampaignIUD UpdateItem`) / новые кампании + `MoveIssues2NewCampaign` | наследует | обновление дерева |

Ничего не создают: калькулятор цены (`PriceCalculatorForm` — только коммерческое предложение
в .docx). Мёртвые: импорт `CampaignImportGrammofonForm`, `CampaignImportMediaPlusForm` (не
входят в `Client.csproj`, Grammofon не скомпилировался бы), `Client/Classes/Exchange/*` и три
процедуры-сироты. Неявно в SQL: `AgitationFraming` заводит служебную акцию для обвязки
политагитации; `SpecialActionIUD` («Ввод остатков», последняя запись — 2024); `job_DeleteEmptyActions`.

Пунктов «Новая акция» и «Добавить кампанию» в дереве и журналах нет: у сущностей 77, 118, 137,
1229, 1255–1257 нет `AddItem`. Добавить кампанию в существующую акцию можно только из карточки.

Права на пункты меню (ArtvisDev): «Внести макет» — 6 групп и 3 личные выдачи, «Веерное
размещение» — 5 групп и 3, «Размещение комбо-модулями» — 4 группы.

### 2.2 Три способа — три поведения

| | Внести макет | Веер-мастер | Комбо-мастер |
|---|---|---|---|
| Проверки `CampaignIUD` (агентство, «нельзя в законченную подтверждённую акцию») | есть | **нет** | есть |
| Менеджерская скидка кампании | максимум пользователя (`CampaignIUD.sql:52`) | 1 (умолчание столбца) — до первого выпуска: тогда `ActionRecalculate` ставит максимум пользователя (`ActionRecalculate.sql:302-304`) | максимум пользователя |
| Пересчёт после создания | нет | нет (закомментирован в процедуре) | да |
| Одна станция | можно | нельзя (`SelectMassmediasStep.cs:54`) | — |
| Пустые кампании, если ничего не поставили | остаются | остаются вместе с акцией | удаляются каскадом |
| Выбор агентства станции | своя копия (`CampaignNewForm.cs:90-112`) | своя копия (`SelectMassmediasStep.cs:100-133`) | своя копия (`SelectComboModuleStep.cs:123-173`) |
| Ошибка создания | глотается, диалог закрывается «ОК» | глотается → NRE дальше | обрабатывается верно |

`CampaignNewForm` (диалог «Добавить кампанию»): тип кампании (все четыре), тип оплаты, группа
станций, станции галочками, агентство — только для пакетной (у пакетной нет станции, создаётся
одна кампания). Право проверяется «Редактировать» у **линейной** кампании (сущность 91) — для
любого типа.

## 3. Карточка акции `ActionForm`

Модальная, открывается из журнала и из трёх мастеров. Сверху — фирма и три цены (по тарифам,
коэффициент скидок, итог); под ними грид «Рекламные кампании» (станция, группа, тип, цены и
скидки, тип оплаты); справа вертикальный тулбар; внизу пять галочек печати и «Ok».

| Кнопка | Доступна | Что делает |
|---|---|---|
| Добавить рекламную кампанию | всегда | `CampaignNewForm`; новая акция сначала записывается `ActionIUD` |
| Удалить рекламную кампанию | выделена кампания | вопрос → `CampaignIUD` Delete → пересчёт; удаляет одну, даже при множественном выделении |
| Редактировать размещение роликов | выделена кампания | `campaign.DoAction(Edit)` → `CampaignForm` с сеткой по типу |
| Веерное редактирование | всегда | `EditIssuesForm` по линейным кампаниям; прав не проверяет |
| Размещение модулями | всегда | вопрос Да/Нет/Отмена → комбо-форма в режиме «выбрать комбо-модуль» или «только размещённые модули»; прав не проверяет |
| Выходы спонсорских программ | выделена спонсорская | `CampaignForm` с сеткой программ |
| График размещения кампании | выделена кампания | медиаплан одной кампании |
| Менеджерская скидка | выделена кампания | `CampaignSetFinalPrice` + пересчёт в одной транзакции; сверх лимита — «разрешающий» |
| Цена рекламной акции | **только при выделенной кампании**, хотя действие уровня акции | распределяет итог по кампаниям, одна транзакция |

«Ok» только печатает отмеченное (счёт, счёт-договор, договор, спонсорский договор, график
размещения акции): всё уже записано, отмены нет. Контекстного меню у грида нет. Активация,
пересчёт, клон, деление, объединение, смена фирмы/создателя — только в меню акции в журнале
(в вебе они уже перенесены, см. `docs/tasks/web-migration.md`, «Операции журнала акций»).

После закрытия формы кампании карточка безусловно перечитывает кампании и статистику (П-15
в `docs/tariffgrid.md`).

## 4. `CampaignForm` — «суперформа» кампании

### 4.1 Пять режимов

Форма получает сетку снаружи (`CampaignForm(campaign, grid)`) и подстраивается под пару
«тип кампании + класс сетки».

| Режим | Тип | Сетка | Кто создаёт форму |
|---|---|---|---|
| Л — линейная | 1 | `RollerIssuesGrid3`, окна станции | `Campaign.EditRollerIssues` (`Campaign.WinForms.cs:154-165`) |
| С-р — спонсорская, ролики | 2 | `RollerIssuesGrid3` (лимит — бонусные секунды, `TimeBonusExceed`) | то же или узел 87 |
| С-п — спонсорская, программы | 2 | `ProgramIssuesGrid2`, ячейки-галочки | `Campaign.EditProgramIssues` или узел 86 |
| М — модульная | 3 | `RollerIssuesGrid3` + модуль из выпадающего списка; клик ставит модуль на весь день | `CampaignModule.DoAction` → база |
| П — пакетная | 4 | `PackModuleGrid`, одна строка × 7 дней + панель деталей | `CampaignPackModule.DoAction` |

Спонсорская кампания делится на части виртуально: `CampaignOnSingleMassmedia.GetContent` строит
две строки с одним `campaignID` — «Программы для спонсоров» (86, пишет `ProgramIssue`) и
«Рекламные ролики» (87, пишет `Issue`).

После закрытия формы вызывающий код ведёт себя четырьмя разными способами: где-то пересчитывает
акцию, где-то пересчёт закомментирован (`Campaign.WinForms.cs:161`), где-то только перерисовывает
дерево.

| Функция | Л | С-р | С-п | М | П |

| Позиционирование | есть | есть | скрыто | серое при штучных тарифах | то же |

### 4.3 Цена универсальности

- Около 145 мест в одном файле зависят от типа: 56 обращений к шести признакам
  (`IsSimplelCampaign`, `IsModuleCampaign`, `IsPackModuleCampaign`, `IsRangeCampaign`,
  `IsSponsorCampaign`, `IsSponsorPrograEditing`), 26 проверок `_tariffGrid is/as …`,
  24 приведения `(IRollerGrid)` без проверки, плюс проверки по окну, модулю и сущности.
  Признаки смешивают тип кампании и тип сетки. Компилятор о пропущенной ветке не
  предупредит: новый тип сетки — обход всех мест вручную.
- Около 1000 из 2101 строк работают только для Л/С-р (и веера): операции по выделению ~450,
  шаблоны ~250, перетаскивание ~190, отмена ~75, подсветки ~65. Выбор модуля для М/П — ~135,
  С-п — ~45, П — ~30.
- Видимое, но бессмысленное: у М до выбора модуля «Обновить», позиция и предмет рекламы
  грузят линейную сетку станции, которую следующий шаг тут же очищает; «Старт» включается
  без сетки. У С-п в списке «Программы» — действия справочника («Удалить программу»,
  «Добавить прайс-лист») посреди формы размещения.
- Ради наследника-веера в базовой форме: конструктор без параметров, 12 virtual-методов,
  14 protected-контролов дизайнера, около 15 веток `IsRangeCampaign` / `is TariffWithRangeGrid`
  и 6 страховок `_campaign == null`.

## 5. Веер `EditIssuesForm`

Наследник `CampaignForm` — единственный. Сетка `TariffWithRangeGrid`: получасовой слот × день
сразу по всем отмеченным линейным кампаниям акции; ячейка — агрегат, конкретного окна за ней нет.

**На чём держится наследование:**
- `TariffWithRangeGrid` реализует `IRollerGrid` заглушками (`Module` — пусто,
  `RefreshCurrentCell` — `NotImplementedException`, `IssueEntity` — null), прайс-лист — фиктивный
  с датами Min/MaxValue; без этого форма скрыла бы панель выпусков или упала бы с NRE;
- тулбар базовой формы приватный — свои кнопки веер вставляет через `tbbReplaceRoller.Owner`
  и заново прячет разделители; дизайнер наследника перекладывает контролы базы в свой сплиттер;
- `ShowWindowIssues` используется как «хук после клика» (двойная перепривязка, П-8); отмена
  шаблона идёт через искусственный `RaiseObjectsDeleted`;
- «Добавленные выпуски» — таблица в памяти с фиктивными отрицательными `issueID`, после
  массовых операций её пересобирают.

**Собственное:** чек-лист кампаний (только линейные, применяется сразу), «Добавленные
выпуски» (пересечение по отмеченным кампаниям), статистика по всей акции, синие/красные/
бирюзовые/оранжевые слоты, номера роликов и значки Н/Д, подсказки на ячейках, «Удалить дубли»,
«Добавить до полного пересечения», Insert/Del/Ctrl+R (в том числе по красным слотам),
перетаскивание слота с предупреждением «фирма уже в окне», шаблоны 1–3 через ветки базовой
формы, справка `Client/Help/veer.html` (ведёт заказчик).

Процедуры: `TariffWindowWithRange` (5 наборов на неделю), `AddRangeIssues` (окно в получасе —
TOP 1 по свободному времени, отдельно для каждой кампании), `MasterIssueDelete`,
`RangeSlotIssues`, `RangeSlotFirmConflict`.

## 6. Комбо-модули `ComboModulePlacementForm`

Самостоятельная форма (не наследник): строки — модули, колонки — дни недели или месяца,
ячейка — минимальный остаток по окнам модуля за день.

| Режим | Откуда | Строки | Создание кампаний | Каскадное удаление пустых |
|---|---|---|---|---|
| 1. Мастер | меню | состав комбо-модуля | лениво, по клику | кампании и акция |
| 2. Только размещённые модули | `ActionForm`, ответ «Нет» | модули с выпусками в акции | запрещено | выключено |
| 3. Достройка по комбо-модулю | `ActionForm`, ответ «Да» | весь состав выбранного комбо-модуля | да, в существующей акции | только созданные в этой сессии |

Связи «акция ← комбо-модуль» в базе нет: комбо-модуль — это фактически сохранённый набор строк
для показа. Модульная кампания без выпусков в грид не попадает (модуль кампании выводится только
через `ModuleIssue`).

**Дублирование.** Около 40% файла (≈600 из 1510 строк, ~24 метода) — копии или адаптированные
копии `CampaignForm`/веера: номера роликов, пустышка, плеер, предмет рекламы, экспорт, цена
акции, обработчики тулбара, перетаскивание (третья копия скелета). Цикл «удалить с журналом
ошибок» существует в пяти копиях (`CF` ×2, `EIF`, `CMPF` ×2).

## 8. Места и запись

| Сетка | Запись | Транзакция и пересчёт |
|---|---|---|
| линейная, ролики спонсорской | `IssueIUD` | явная: выпуск + `ActionRecalculate(false)` |
| модульная (в `CampaignForm` и комбо) | `IsModuleExist` + `ModuleIssueIUD` (строки `Issue` во все окна модуля, проверка `hlp_IssueVerify`) | явная; в комбо ещё создание акции/кампании |
| программы спонсорской | `ProgramIssueIUD` (снятие галочки удаляет; возможен `ProgramIssueDeleteBonusError`) | явная |
| пакетная | `PackModuleIssueID` (строки `PackModuleIssue` и `Issue`) | явная |
| веер | `AddRangeIssues` (курсор по кампаниям, `IssueIUD` на каждую), `MasterIssueDelete` | только на `AddRangeIssues`; пересчёт отдельно, с коррекцией платежа |

`ActionRecalculate` пересчитывает всю акцию и, если подтверждённая акция подешевела, вызывает
`PaymentAction_CorrectByActionTotalPrice`. Запись — только через IUD-процедуры: они же ведут
счётчики занятости окна (`timeInUse*` и др.), триггеров нет.

## 10. Дефекты, найденные при обследовании

Номера сквозные, на них ссылается план веба.

**Состояние на 03.10.2026.** Д-4, Д-5, Д-7, Д-9 воспроизведены вживую в клиенте на ArtvisDev.
- **Д-4 исправлен** (решение Миши): «Отмена» в выборе агентства пропускает только эту станцию
  (остальные добавляются, пропущенные — одним сообщением; станция без агентств пропускается
  без окна выбора; пропущены все — диалог не закрывается); список собирается заново на каждое
  «Ок»; `ActionForm.AddCampaign` пишет кампании по одной — отказ по одной (например, такая уже
  есть в акции, два случая в прод-логе 18.09 и 29.09) не мешает остальным, неудавшиеся —
  в итоговом сообщении. «Всё или ничего» отвергнуто. Текст `UIX_Campaign` — без «Операция
  прервана.» (`ArtvisDB/Scripts/uix-campaign-message-deploy.sql`). На Artvis сценарий с дублем
  был почти недостижим: у всех действующих станций по одному действующему агентству.
- **Д-5 исправлен**: перед вставкой акции, пришедшей из карточки, форма комбо запоминает её
  параметры и при откате транзакции первого клика возвращает объект в «несохранённое»
  состояние — следующий клик записывает ту же акцию, карточка её видит. Под администратором
  отказ даёт «Показывать первые» на днях с занятой первой позицией (у менеджера — клик по
  прошедшему дню).
- **Д-7 исправлен** (решение заказчика): в сетке комбо колонка «Тип оплаты», строка = модуль
  в конкретной модульной кампании. Клик и перенос идут в кампанию строки; при ответе «Да» и
  в мастере добавляются строки модулей с типом оплаты из шага (кампания создаётся по клику).
  Строки строит форма из выпусков и кампаний акции; процедура `ComboModuleActionModulesRetrieve`
  удалена (`ArtvisDB/Scripts/combo-module-action-modules-drop-deploy.sql`).
- **Д-9 не исправляем** (решение Миши 04.10.2026). Сбрасывают скидку оба места — `CampaignIUD
  AddItem` и `ActionRecalculate` (переход кампании 0→N выпусков); ставится «максимум
  пользователя» — самый глубокий коэффициент, разрешённый тому, кто делит, на период новой
  кампании (у админа 1,0). Почему так и оставляем: у новых частей другие даты, на них у
  менеджера могут действовать другие лимиты, и перенос старого коэффициента мог бы их нарушить;
  деление — ответственная операция, результат пользователи проверяют и ставят скидку сами,
  нареканий не было. Для веба: поведение повторить как есть.
