# Медиаплан («График размещения»): справочник

Исследование 2026-09-27, код не менялся. Всё, что в десктопе (qd2) печатает
медиаплан: точки входа, варианты, раскладка листа Excel, SQL, настройки,
тонкости и известные долги. План переноса в веб — `docs/tasks/web-mediaplan.md`.

В интерфейсе медиаплан называется **«График размещения»**. Это не Crystal, а
выгрузка в Excel через COM (`FogSoft.WinForm/Classes/Export`, `ExportManager`,
`IDocumentSheet`). Весь генератор — один класс `Client/Classes/MediaPlan.cs`
(~1000 строк).

## 1. Карта вариантов

Вариант задаётся тремя осями:

- **Источник и раскладка** — что печатаем и как режем на листы (см. §3):
  - **К** — «по кампаниям»: лист на кампанию (или кампанию × месяц);
  - **С** — «по станциям»: лист на агентство, внутри блок на каждую станцию.
- **Разбивка по времени**: целиком / по месяцам (`FrmMonths`) / за период (`FrmDateSelector`).
- **Выборочно по роликам** (`SelectionForm` ролика): печатаются только выбранные ролики,
  заголовок меняется на «Частичный график размещения…», стоимость считается по ним же.

  ├─ [за период]   FrmDateSelector (по умолчанию даты акции/кампании)

          ├─ раскладка К: PrintCampaignInfo по каждой кампании (× месяц)

Экспорт синхронный, на UI-потоке (STA), курсор ожидания; при падении
посередине показывается то, что успело записаться (`FinishExport`).

## 3. Раскладки листов

### К — «по кампаниям» (`PrintCampaignInfo`, `:474`)

- Лист на кампанию; при разбивке по месяцам — лист на **кампанию × месяц**
  (месяц попадает в лист, если лежит между `StartDate` и `FinishDate` кампании).
- Имя листа: `«{месяц} {год} »{имя кампании} ({campaignID})`, обрезается с `...`
  до 30 символов (`GetSheetName`, `:515`).
- Станции внутри листа: у пакетной кампании — список станций пакета
  (`CampaignPackModule.GetUniqueMassmedias` → `GetUniqueMMsForPackModuleCampaign`),
  у остальных — одна станция кампании.
- Тип кампании определяет форму блока (§4): у линейной есть колонка «Цена»,
  у спонсорской — блок «Программы».

### С — «по станциям» (`PrintActionInfo`, `:386`)

- `GetUniqueMMsForAction` (одна акция или `@actionIDString`) → пары
  (станция, агентство); лист на **агентство** (имя листа = имя агентства),
  порядок — первого появления.
- Внутри листа — блок на каждую станцию агентства, плюс станции спонсорских
  кампаний акции (второй набор процедуры), даже если у них нет выпусков роликов.
- Данные блока грузятся с `@agencyId` и `campaignTypeId = NULL` → форма блока
  как у модульной (без колонки «Цена»), блок «Программы» печатается всегда.
- Сводный режим (набор акций) — та же раскладка; заголовок
  «График размещения по нескольким акциям № 1, 2, 3», заказчик — все фирмы через запятую.

**Группировка станций мертва.** `MediaPlanCampaignGroups` задумывалась
склеивать станции с одинаковыми роликами и днями в один блок
(«Радиостанция: А, Б»), но `MediaPlanMassmedia.CompareTo` захардкожен на
`return 1` (`MediaPlanCampaignGroups.cs:135-142`). Фактически: один блок на
станцию в порядке появления. Поэтому `@massmediaIDString` всегда содержит
одну станцию, а множитель `ids.Length` в итогах (`:699, :703`) всегда 1.

## 4. Блок станции (строки и колонки)

Шрифт листа Tahoma 8, альбомная ориентация. `currentY` — текущая строка,
блоки идут друг под другом с отступом 3 строки.

1. **Заголовок** (кол. 3, жирный 12pt): «График размещения для рекламной акции № N»
   / «Частичный график…» (выборочно) / «…по нескольким акциям № …».
2. **Шапка** (кол. 1, столбцом): Заказчик, Исполнитель (агентство с префиксом),
   Радиостанция, СМИ, Территория распространения (`GroupName` станции).
3. **Ролики** (кол. 4 у линейной, иначе 3): «Ролики:», затем по строке на ролик:
   `№i`, длительность, количество выходов, название (+ « - предмет рекламы»
   по галочке). Номер `i` — порядковый **в пределах блока**, он же пишется в сетку.
4. **Программы** (кол. 3–6, только спонсорская кампания и раскладка С):
   дата, время, название спонсорской программы.
5. **Таблица времени** (кол. 1..): заголовок «Время | Коммент. | [Цена] | Прод-ть»,
   строка на тайм-слот. Ключ строки — время (у линейной — время + цена, т.е. одно
   время с разной ценой окна даёт две строки). «Прод-ть» — суммарная длительность
   выпусков в этом слоте. Формат времени `time`, цена — денежный.
6. **Сетка** справа от таблицы времени (кол. 5 у линейной, иначе 4):
   - две строки заголовка: дата (повёрнута на 90°) и день недели;
   - колонки: **по месяцам** — все дни месяца подряд, включая пустые;
     **иначе** — только даты, где есть выпуски;
   - ячейка: номера роликов через запятую с меткой позиции `(F)` первый,
     `(S)` второй, `(L)` последний (включая «перенесённые» позиции);
   - выходные залиты серым `#D2D2D2`, рамки у всей сетки;
   - строка под сеткой — число выпусков по дню.
7. **Итоги** (кол. 3): «Всего трансляций», «Время трансляций», стоимость:
   - скидки нет → «Стоимость спланированной рекламы»;
   - скидка есть → «…по тарифам», «Скидка: x%», «…с учетом скидки»;
   - галочка «Скрыть стоимость по тарифам» → только «Стоимость спланированной рекламы»;
   - «В том числе НДС (5%)», если налог > 0 (ставка в тексте **захардкожена**).
   Стоимость — `Campaign.GetPriceByPeriodWithTax` → `GetPriceByPeriod`
   (output-параметры `price`, `tariffPrice`, `taxPrice`) по каждой кампании
   блока за период листа/месяца/кампании, с `@rollerIDString` при выборочной печати.
8. **Подписи**: «Исполнитель:» (+ картинка `Agency.SignatureBytes` в кол. 7 при
   галочке), через 4 строки «Заказчик:», затем «Контактное лицо: …» создателя
   акции — только раскладка К и только при `PrintContactPersonInfo = true`
   (по умолчанию true) в конфиге.

## 7. Тонкости и ловушки

- **Всегда фактическое время.** `Show(isFact)` делает `isFact = true`
  (коммит 4a766ad, 28.06.2026, «Медиа-планы должны показывать фактическое время»).
  Пары «Fact / не Fact» в коде — пережиток, по данным это одно и то же.
  Но: список месяцев у **акции** строится `GetMonthes` без `@isFact` (= 0,
  по оригинальным окнам), а печать — по фактическим. Выпуск, перенесённый через
  границу месяца, может дать месяц без данных или не показать нужный.
- **«График размещения» акции ≠ галочка в `ActionForm`.** Действие у акции
  печатает раскладку К (лист на кампанию), галочка — раскладку С (лист на
  агентство). Раскладка С без месяцев, периода и выборочности.
- В раскладке К при выборе месяцев на уровне акции кампания получает лист на
  месяц, если месяц внутри её дат, даже без выпусков в нём (не выборочно
  `LoadData` всегда «есть данные»). Тогда печатается блок с пустыми таблицами;
  стоит проверить глазами.
- `_columnWithRollerName` не сбрасывается между блоками: если в блоке нет
  роликов, сетка всё равно рисуется по ширине прошлого блока.
- В раскладке К после шапки лишняя пустая строка (`currentY++` на `:508`),
  в С её нет — у двух раскладок разный вертикальный ритм.
- Набор 3 при `campaignTypeId IS NULL OR = 4` фильтруется на **первую** станцию
  из `@massmediaIDString` — рассчитано на склейку станций, которой больше нет.
- Форматы дат, денег (`{0:c}`) и процентов берутся из текущей культуры потока
  (сохраняется и восстанавливается вокруг экспорта).
- Имя листа Excel ≤ 31 символа и без `[]:*?/\`. `MSExportDocument.GetNewSheet`
  при совпадении имени оставляет лист с именем по умолчанию («Лист2»); длину и
  символы не проверяет — имя агентства в раскладке С уходит как есть
  (длинное или с `/` уронит экспорт на COM-исключении).
- `Action.GetCampaigns` может вернуть `null` для удалённой кампании →
  NRE в раскладке К (`IMPROVEMENTS.md`, C#-02).

## 8. Производительность (история)

- `MediaPlanRetrieve_v2` + `OPTION (RECOMPILE)`: худший случай 39,6 с → 0,33 с (`IMPROVEMENTS.md`).
- `GetUniqueMMsForAction`: `ROW_NUMBER` + `RECOMPILE`, 1,7–2 с → 50–200 мс.
- N+1 по `Campaigns` в итогах сводного плана убран кэшем (`2e36d7d`).
- Запись в Excel пачками `SetValuesForRange` (`e686c11`) — COM-вызовы были узким местом.

Остаток: `MediaPlanRetrieve_v2` зовётся по разу на станцию (+ по разу на
кампанию × месяц для списка роликов), `GetPriceByPeriod` — на каждую кампанию
каждой станции, `Massmedia.GetMassmediaByID` / `Agency.GetAgencyByID` — на каждый блок.
