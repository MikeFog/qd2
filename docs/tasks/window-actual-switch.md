# Фактическое окно везде: карта мест и план работ

Статус: инвентаризация 07.10.2026 (76 SQL-объектов, 17 файлов C#, около 350 мест), до правок. Выводы — чтением
кода и `SELECT` на ArtvisDev; рискованные места перепроверены отдельно; вживую сценарии не воспроизводились.
Справочник по самим полям (что такое «исходное» и «фактическое», кто их пишет) — `docs/window-original-actual.md`.
Решения владельца по вопросам §3 — в журнал (§7).
Открытые вопросы с поправками сверки от 07.10.2026 (Р-1…Р-17, О-1…О-8) — `docs/tasks/window-actual-open-questions.md`.

Правило Миши от 07.10.2026: везде используется фактическое окно и фактическое время. Исходное значение остаётся только для истории переносов.

**Сокращения в ссылках.**
- `SP/` = `ArtvisDB/dbo/Stored Procedures/`, `T/` = `ArtvisDB/dbo/Tables/`, `Fn/` = `ArtvisDB/dbo/Functions/`.
- C#: `Cls/` = `Client/Classes/`, `Ctl/` = `Client/Controls/`, `Frm/` = `Client/Forms/`, `Web/` = `FogSoft.Web/Infrastructure/`.
- Д — десктоп, В — веб.

**Классы мест.**
- П — переключить на фактическое.
- О — оставить: это ключ тарифного слота или место без эффекта.
- И — законная история переносов.
- М — мёртвый код.
- Р-n — нужно решение Миши, см. §3.

## 4. Исходное время окна (TariffWindow.windowDateOriginal, dayOriginal)

- **Что это.** windowDateOriginal = dayOriginal + Tariff.time у 100% окон тарифов. Значение пишется один раз (`SP/sl_GenerateTariffWindowsDay.sql:17-40`, `SP/GenerateTariffWindowByTemplate.sql:88`, `SP/TariffWindowIUD.sql:153`) и потом не меняется. «Перенос времени выхода» (`SP/TariffWindowMoveTime.sql:121-124`) и паспорт окна (`SP/TariffWindowIUD.sql:123-137`) меняют только фактическое время. Значит, это **время окна до переноса**, то есть история переноса окна. Одновременно это естественный ключ слота: пара (станция, windowDateOriginal) уникальна, а по фактическому времени 390 коллизий (Искатель 236/237/241, 12.2025).
- **Принцип применим без исключений по смыслу.**
  - Всё, что показывает, отбирает или считает эфир, работает по windowDateActual / dayActual.
  - Узнавание слота по истории остаётся на исходном времени. Это отсев дублей при генерации, групповые операции по строке расписания (Р-1), поиск окна на новой дате при клоне и переносе дня (`SP/CampaignTransferDay.sql:136,142,157`, `SP/TariffWindowRetrieveByDate.sql:12`), модуль как набор слотов дня. Это законное использование «истории окна».
- **Что меняется.**
  - название окна: `SP/TariffWindowRetrieve.sql:134,169`;
  - сообщения трафика: `SP/TariffWindowMoveTime.sql:131,132`, `Cls/TrafficManagement.cs:150,260,279`;

  - приписка в модульной сетке;
  - журнал удалённых выпусков, журналы с отбором по времени, дерево журнала, паспорт замены ролика.
- **Масштаб.** 32 246 сдвинутых окон с 2025 года; 91% из них — Ретро FM (станции 200/205/208/211), 2-е полугодие 2026. В них 56 857 выпусков, будущих — 13 935 окон и 8 207 выпусков. Окно у этих выпусков правильное, исправляется только показанное время.
