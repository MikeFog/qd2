# Реклама в период политической агитации — программа тестирования

Документ для тестировщиков. Техническое описание реализации — в
`docs/tasks/political-agitation-ads.md`, бизнес-правила — в
`docs/business-logic.md`, раздел «Политическая агитация».

**Суть функционала одной фразой:** ролик политической агитации по закону о
выборах обязан выходить в эфир «обрамлённым» — перед ним идентификатор
локального СМИ и анонс агитации, после него идентификатор федерального СМИ.
Система добавляет эту обвязку сама, менеджер её не размещает и не видит в своей
кампании.

---

## 0. Что должно быть развёрнуто

Без этого тестировать бессмысленно — проверьте до начала.

1. **Скрипт данных** `ArtvisDB/Scripts/political-agitation-seed.sql` (создаёт
   новые типы роликов, тексты сообщений, поля в карточке станции и вкладку
   паспорта). Скрипт идемпотентный, повторный запуск безопасен.
2. **Процедуры и функции**: `AgitationFraming` (новая), `fn_AgitationChainFirst`
   (новая), `ActionActivate`, `ActionDeactivate`, `IssueIUD`, `hlp_IssueVerify`,
   `RollerSubstitute`, `IssueTransfer`, `CampaignIUD`, `ActionIUD`,
   `MassmediaIUD`, `massmediaPassport`, представление `vMassmedia`.
3. **Свежая сборка клиента** (`Merlin.exe`) — есть правки в C#.
4. **Перезапустить клиент после деплоя** — метаданные форм кэшируются, иначе
   новая вкладка в карточке станции не появится.

Тестируем на копии рабочей базы, не на проде.

## 1. Подготовительная работа

### 1.1. Создать ролики четырёх новых типов

Обычным способом (журнал роликов → создать), тип выбирается в поле «Тип ролика»:

| Тип ролика | Назначение | Кто размещает |
|---|---|---|
| Политическая агитация | ролик кандидата, за него платят | менеджер |
| Локальное СМИ (агитация) | идентификатор перед агитацией | система |
| Анонс политической агитации | «а теперь политическая агитация» | система |
| Федеральное СМИ (агитация) | идентификатор после агитации | система |

Требования:
- у ролика **политической агитации обязательно заполнить «Предмет рекламы»** —
  иначе активация отбракует его обычной проверкой, к нашей задаче отношения не
  имеющей;
- у всех роликов указать реальную длительность — она вычитается из свободного
  времени окна, на этом строятся проверки;
- если планируете доводить дело до выгрузки в DJin, укажите существующие файлы,
  иначе строки в выгрузке будут ссылаться в пустоту (это не дефект логики).

### 1.2. Заполнить карточку радиостанции

Карточка радиостанции → вкладка **«Политическая агитация»** → три выпадающих
списка: локальное СМИ, анонс, федеральное СМИ.

- В каждом списке видны только ролики соответствующего типа. **Пустой список
  означает, что роликов такого типа ещё не создано** — вернитесь к шагу 1.1.
- Поля необязательные: станцию можно сохранить и с пустыми полями. Но пока они
  пусты, разместить агитацию на этой станции не получится (см. сценарий 1).
- Заполните поля минимум для двух станций, если будете проверять веерные акции.

### 1.3. Прочее

- Фирма-заказчик (кандидат) — обычная фирма.
- Желательно иметь станцию, где уже используются **ручные** идентификаторы СМИ
  (типы 4 и 5) — для сценария 12.
- Полезно заранее найти почти заполненное окно — для сценария 10 (переполнение).

## 2. Когда что происходит и какие проверки выполняются

Главный принцип: **обвязка привязана к рекламному окну, а не к акции менеджера.**
Она появляется, когда в окне появляется подтверждённая (эфирная) агитация, и
исчезает, когда последняя такая агитация из окна уходит. Живёт обвязка в
отдельной служебной акции фирмы «(Служебная) Обвязка политагитации».

| Событие | Что делает система |
|---|---|
| Размещение агитации в **черновике** акции | Ничего не добавляет. Поля станции не проверяются — всё это произойдёт при активации |
| **Активация** акции с агитацией | Сначала проверяет, что у всех задействованных станций заполнены три ролика обвязки. Если хоть у одной не заполнены — активация не проходит целиком. Затем в каждое окно с агитацией добавляет недостающую обвязку |
| Размещение агитации в **уже активированной** акции | Выпуск сразу эфирный, поэтому обвязка добавляется сразу же. Если поля станции не заполнены — размещение запрещено |
| Второй кандидат в **то же окно** | Обвязка не дублируется — она уже там |
| В окне уже стоят **ручные** идентификаторы 4/5 | Они не трогаются и не дублируются, добавляется только недостающее (анонс) |
| **Удаление** ролика агитации | Если в окне не осталось подтверждённой агитации — обвязка снимается. Если осталась (другой кандидат) — остаётся |
| **Деактивация** акции | Обвязка снимается: агитация вернулась в черновик и в эфир не идёт. При повторной активации появится снова |
| **Удаление** кампании или акции | Обвязка снимается |
| **Перенос** выпуска в другое окно (мышью) | Обвязка переезжает: из старого окна снимается (если там больше нет агитации), в новом создаётся |
| Перенос при активации (режим поиска окна) | Обвязка создаётся в том окне, куда выпуск фактически встал |
| **Замена ролика** в размещении | Нельзя заменить обычный ролик на агитационный и наоборот |
| **Позиционирование** (первый/второй/последний) | Для агитации и обвязки не применяется, выбрать нельзя |
| **Смешение** в одной акции | Агитацию и обычную рекламу нельзя размещать в одной акции — ни в каком порядке |
| **Переполнение** окна | Обвязка добавляется, даже если места нет: окно уходит в минус и подсвечивается в трафике красным. Сам ролик агитации при этом обычным порядком не активируется, если не влезает |
| **Выгрузка для DJin** | Порядок внутри блока, два случая — см. пояснение сразу под таблицей |
| **Медиапланы и распечатки** клиента | Обвязка в них не попадает |

### Порядок в выгрузке для DJin

Важно не путать два разных «локальных СМИ»: **ручной** идентификатор (тип 4)
обрамляет **весь блок**, а **автоматический** (тип 44) — только политическую
часть внутри блока. То же самое с федеральными (5 и 55).

**Случай А — в окне есть ручные идентификаторы (4 и 5).** Автоматические 44/55
не добавляются, система дописывает только анонс:

```
[4] ручной локальный СМИ      <- первый во всём блоке
    джингл влёта
    обычные ролики
    анонс агитации
    ролики кандидатов
    джингл аута, музыкальная добивка
[5] ручной федеральный СМИ    <- последний во всём блоке
```

**Случай Б — ручных идентификаторов в окне нет.** Обвязка автоматическая и
обрамляет только политическую часть, а не весь блок:

```
     джингл влёта
     обычные ролики
[44] локальный СМИ (авто)
     анонс агитации
     ролики кандидатов
[55] федеральный СМИ (авто)
     джингл аута, музыкальная добивка
```

Джинглы влёта и аута остаются на своих местах: политическая часть встаёт **до**
джингла аута, а не после него.

Обычные ролики в обоих случаях идут как раньше, со своим позиционированием —
их порядок функционалом агитации не меняется.

В самом txt-файле все ролики обвязки записаны как обычные (`c`) — по ним не
видно, что они служебные, различить их можно только по имени файла.

### Сообщения, которые должен увидеть пользователь

- «У радиостанции не заполнены ролики обвязки политической агитации (карточка
  радиостанции, вкладка "Политическая агитация")…»
- «В одной рекламной акции нельзя размещать политическую агитацию вместе с
  другой рекламой…»
- «Для роликов политической агитации позиционирование не применяется…»
- «В окне уже есть ролик с типом "Анонс политической агитации"…»

Тексты должны выводиться человекочитаемо. Если видите на экране голый код
вроде `AgitationMixError` — это дефект (не залит скрипт данных).

## 3. Сценарии для проверки

Отмечайте фактический результат. Все сценарии — на линейной (простой) кампании,
если не указано иное.

### Базовые

**1. Станция не настроена — активация запрещена**
Очистить три поля на вкладке «Политическая агитация» у станции → создать акцию
с роликом агитации → активировать.
Ожидается: активация не проходит, сообщение про незаполненные ролики обвязки,
ни один выпуск акции не активирован.

**2. Черновик обвязку не создаёт**
Заполнить поля станции → создать акцию с агитацией, **не активировать** →
кликнуть по окну.
Ожидается: в окне только ролик кандидата, обвязки нет.

**3. Активация создаёт обвязку**
Активировать акцию из сценария 2 → кликнуть по окну.
Ожидается: в блоке «Все выходы в эфир» четыре строки — ролик кандидата и три
ролика обвязки (нулевая цена, создатель admin). Свободное время окна уменьшилось
на сумму длительностей всех четырёх.

**4. Размещение в уже активированной акции**
Открыть активированную акцию → разместить ещё один ролик агитации в другое окно.
Ожидается: обвязка появляется в этом окне сразу, без повторной активации.

**5. Второй кандидат в то же окно**
Создать вторую акцию (другой кандидат) → разместить агитацию в то же окно →
активировать.
Ожидается: добавился только ролик второго кандидата, обвязка не задвоилась.

**6. Удаление одного из двух**
В окне из сценария 5 удалить ролик первого кандидата.
Ожидается: обвязка осталась (второй кандидат ещё в эфире).

**7. Удаление последнего**
Удалить и второй ролик агитации.
Ожидается: обвязка исчезла, свободное время окна вернулось к исходному.

### Жизненный цикл акции

**8. Деактивация и повторная активация**
Акция с агитацией активирована → деактивировать → посмотреть окно → активировать
снова.
Ожидается: после деактивации обвязки нет, после повторной активации она вернулась.

**9. Удаление кампании и акции**
Удалить кампанию с агитацией (и отдельно — акцию целиком).
Ожидается: обвязка из окон удалена, «сирот» не осталось.

### Границы и запреты

**10. Переполнение окна**
Разместить агитацию в почти заполненное окно так, чтобы обвязка не помещалась →
активировать → открыть трафик.
Ожидается: обвязка всё равно добавлена, окно ушло в минус и подсвечено красным.
Если не помещается сам ролик кандидата — он не активируется, как обычно.

**11. Запреты**
- попытаться задать агитации позиционирование (первый/последний);
- добавить обычный ролик в акцию, где есть агитация;
- добавить агитацию в акцию, где есть обычная реклама;
- заменить обычный ролик на агитационный и наоборот.
Ожидается: каждое действие запрещено с понятным сообщением.

**12. Блок с ручными идентификаторами СМИ**
Найти окно, где уже стоят ручные ролики типов 4 и 5 → разместить туда агитацию →
активировать.
Ожидается: ручные ролики не задвоились и остались на своих местах, добавился
анонс и ролик кандидата.

### Переносы

**13. Перенос выпуска мышью**
Перенести подтверждённый ролик агитации в другое окно.
Ожидается: в старом окне обвязки не осталось (если там не было другой агитации),
в новом появилась.

**14. Перенос при активации**
Активировать акцию с включённым режимом поиска другого окна так, чтобы выпуск
не прошёл в своём окне и был перенесён.
Ожидается: обвязка создана в том окне, куда выпуск фактически встал.

### Выгрузка

**15. Порядок в файле для DJin**
Сформировать выгрузку сетки вещания на день с агитацией → открыть txt.
Проверить оба случая (см. «Порядок в выгрузке для DJin» в разделе 2):
- блок **без** ручных идентификаторов: обычные ролики → локальное СМИ (авто) →
  анонс → ролики кандидатов → федеральное СМИ (авто);
- блок **с** ручными идентификаторами (сценарий 12): ручной локальный первым во
  всём блоке, ручной федеральный последним, а внутри — обычные ролики → анонс →
  ролики кандидатов; автоматических 44/55 в этом блоке быть не должно.

Отдельно проверить, что порядок и позиционирование обычных роликов в блоках
**без** агитации не изменились по сравнению с прежней выгрузкой.

**16. Медиаплан клиента**
Распечатать медиаплан акции кандидата.
Ожидается: только ролики кандидата, обвязки в документе нет.

## 4. Где смотреть результат

| Что проверяем | Где смотреть |
|---|---|
| Обвязка создана/снята | Форма кампании → клик по окну → блок **«Все выходы в эфир»** |
| Кому принадлежит обвязка | Там же: фирма «(Служебная) Обвязка политагитации», создатель admin, цена 0 |
| Свободное время окна | Статус окна на форме кампании |
| Переполнение | Форма трафика — красная ячейка |
| Служебная акция | Журнал акций, фирма «(Служебная) Обвязка политагитации» |
| Выгрузка | Итоговый txt-файл сетки вещания |

## 5. Что НЕ является дефектом

Проверьте по этому списку, прежде чем заводить баг.

- **Служебная акция видна в журнале акций.** Так задумано, специально не
  прячется.
- **Обвязка не видна в блоке «Выходы в эфир этой кампании».** Она принадлежит
  служебной кампании, а не кампании клиента — по замыслу.
- **Обвязка не попадает в медиапланы и распечатки клиента.** Так и должно быть.
- **Окно уходит в минус и краснеет.** Ожидаемое поведение: обвязка обязательна
  по закону, поэтому добавляется независимо от свободного времени. Разбирается
  трафиком вручную.
- **Создатель обвязки — admin, а не менеджер.** Сделано намеренно, чтобы
  статистика по менеджерам не получала чужих выпусков.
- **Цена роликов обвязки — ноль.** Обвязка не продаётся.
- **Пустые выпадающие списки на вкладке станции** — значит, роликов нужного
  типа ещё не создано, это не поломка формы.

### Осознанно не поддерживается

Не заводить как дефекты, это отложенные решения:

- размещение агитации в **модульных и пакетных** кампаниях (агитация покупается
  линейно);
- агитация через **внешний импорт** (Граммофон, МедиаПлюс);
- позиционирование агитации (запрещено намеренно);
- смешанные акции «агитация + обычная реклама» (запрещено намеренно, из-за
  отчётности перед избиркомом).

## 6. Что приложить к отчёту о дефекте

Чтобы разбор не превратился в переписку:

1. Станция, дата и время рекламного окна.
2. Номер акции и кампании (и номер служебной акции, если про обвязку).
3. Шаги, которые привели к проблеме, и что ожидалось.
4. Скриншот блока «Все выходы в эфир» по этому окну.
5. Время, когда воспроизвели — для поиска в `logs/qd2.log`.
6. Для дефектов выгрузки — сам txt-файл и номер блока в нём.

## 7. Быстрый чек-лист (10 минут)

Минимальный прогон, чтобы убедиться, что сборка вообще рабочая:

- [ ] Вкладка «Политическая агитация» открывается в карточке станции и
      сохраняется
- [ ] Активация без заполненных полей станции — запрещена с сообщением
- [ ] Активация с заполненными — в окне появились три ролика обвязки
- [ ] Второй кандидат в то же окно — обвязка не задвоилась
- [ ] Удаление последней агитации — обвязка ушла
- [ ] Обычная (неполитическая) акция активируется как раньше, ничего лишнего в
      её окнах не появилось
