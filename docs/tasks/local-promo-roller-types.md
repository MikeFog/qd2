# Локальное промо: два новых типа роликов

Статус: реализовано 02.10.2026, проверено на ArtvisDev. Деплой —
`ArtvisDB/Scripts/local-promo-roller-types-deploy.sql`.

## Типы (`iRollerActionType`)

| ID | Название | Реклама? |
|---|---|---|
| 8 | Локальное промо со спонсором | да |
| 9 | Локальное промо без спонсора | нет — только для вычистки In/Out в выгрузке |

## Правило выгрузки DJin (`BlockManager.ProcessBlock`)

Порядок в блоке:

```
BT → Локальное СМИ (4) → промо без спонсора (9) → влёт (In) → промо со спонсором (8)
   → обычная реклама → 44 → 7 → агитация (6) → 55 → аут, добивка → Федеральное СМИ (5) → E
```

- Влёта нет — промо со спонсором встаёт сразу за промо без спонсора (или первым).
- Склеенный блок, влёт в середине (06.10.2026, Тюмень, «Европа Плюс» 17.10 6:35+6:36):
  промо без спонсора встаёт вплотную перед первым влётом блока, а не в начало блока.
  Влёт помечается `j-in` при печати и снимается в `BlockManager.Process`. Промо со спонсором
  (8) в этом случае не трогали (решение Миши).
- Несколько промо одного вида — в исходном порядке сетки, ограничений по количеству нет.
- Рекламы в блоке нет (только 4/5, 9, анонс, обвязка агитации, добивка) — влёт и аут
  вычищаются. Рекламой считаются обычные ролики, новости/программы, агитация (6) и
  промо со спонсором (8).
- В файл промо пишется строкой `c-type-8` / `c-type-9` (с 08.10.2026; раньше — `c`), громкость
  рекламы, без суффикса даты в имени файла. Метку снимает добивщик (см. ниже).

## Добивщик «Европы Плюс»: в блоке с промо нет анонса (08.10.2026)

Заказчик: промо (8/9) и анонс (`NationalDecroElements`) в одном блоке несовместимы. Правило
только для «Европы Плюс», остальные станции добиваются как раньше.

- qd2 оставляет метки `c-type-8` / `c-type-9` в файле, как `c-type-4` / `c-type-5`
  (`BlockManager.NormalizeAgitationMarker`). Сырые `c-type-N` DJin принимает без замечаний:
  Авторадио идёт мимо добивщика с `c-type-4/5` с декабря 2025 (подтвердил Миша).
- Добивщик (`C:\Work\AdvertAg\Broadcast Schedule\sources`, свой локальный git с 08.10.2026 —
  коммит 4ddbe90; собирается `pyinstaller schedule.spec` в `dist\schedule.exe`):
  - `AudioBlock.save` снимает `c-type-8/9` у всех станций (как 4/5);
  - `AudioBlockEurope.build_block`: если в блоке (весь `BT`..`E`, склеенная цепочка тоже)
    есть 8 или 9, вместо пары «шифт + анонс» ищется один шифт —
    `AudioFile('Shift', minduration=остаток)`, перелёт не больше `Delta`. Песня и торт
    подбираются как раньше. Шифта нет или он длиннее — `BlockError`, как при любом недоборе;
    два шифта или анонс как запасной вариант не ставятся (решение Миши).
- Выкатка: сначала добивщик, потом qd2 и веб. В обратном порядке старый добивщик пропустит
  `c-type-8/9` в DJin.
- Проверка (08.10.2026, выгрузки Европы 08.02.2025 по 4 городам, промо 8/9 проставлены в них
  искусственно в раскладке `BlockManager`; старый код из бэкапа против нового): без промо результат побайтно тот же; в 32 блоках с промо анонсов нет, меток `c-type`
  в результате нет, блоки без промо не изменились. Из 16 промо-блоков, где раньше стоял анонс,
  5 закрылись шифтом, 11 ушли в `BlockError` (остаток 22–31 с больше самого длинного шифта
  15,6 с). Библиотека и плейлисты локальные, на проде доля будет другой.

Ответы заказчика (01.10.2026): порядок «Локальное СМИ → промо без спонсора → In»;
повторы промо в блоке разрешены; проверки при размещении — как для обычных роликов;
в процент заполнения входят; промо без спонсора — не реклама (правило вычистки In/Out).

## База: промо = обычный ролик

| Объект | Правка |
|---|---|
| `hlp_IssueVerify`, `ActionActivate`, `IssueTransfer` | `DisabledInsertSimpleRoller` (окна с `maxCapacity > 0`) — `rolActionTypeID in (1, 8, 9)` |
| `stat_FillPercentage` | 8/9 входят в процент заполнения |
| `rpt_Grid_v3` | 8/9 в ветке без `DISTINCT` (иначе один промо дважды в окне схлопывался) |

Проверка времени окна (`WindowOverflow`) действовала на все типы и раньше.

## Позиционирование запрещено

Ответ заказчика (02.10.2026): позиционирование на промо не распространяется. Место промо в
блоке задаёт тип ролика при выгрузке, а позиция (первый/второй/последний) только заняла бы
флаг окна (`isFirst/Second/LastPositionOccupied` — обычной рекламе `FirstLastIssueError`)
и дала бы наценку. Деплой — `ArtvisDB/Scripts/promo-position-forbidden-deploy.sql`.

| Объект | Правка |
|---|---|
| `hlp_IssueVerify` | 8/9 с `positionId <> 0` → `PromoPositionForbidden` (как `AgitationPositionForbidden` для 6/7/44/55). Покрывает добавление и изменение выпуска (`IssueIUD`, в т. ч. «Изменить позиционирование»), модули, пакеты, перенос дня |
| `IssueIUD` | UpdateItem без `@rollerID` (процедура берёт ролик из выпуска) теперь берёт по нему и тип ролика — раньше тип оставался пустым и проверки по типу не срабатывали |
| `RollerSubstitute` | выпуск с позицией на промо не заменяется, строка в журнале ошибок замены (`iMessageToSubtitute`) |

Уже размещённые промо с позицией запрет не трогает (скрипт деплоя их показывает).

Скрипт деплоя несёт полные тексты `IssueIUD` и `RollerSubstitute`, поэтому в них же — защита
цены из `b82ef55` (длительность ролика и цена из базы, а не от клиента; на проде с 2026-10-03,
`issue-price-from-db-deploy.sql`): выкатка промо её не откатывает, порядок двух скриптов любой.

Не тронуто: `rollerDurationSum` в `rpt_Grid_v3` (итог «реклама» в отчёте «Сетка вещания»)
по-прежнему считает только тип 1; выгрузки VideoDJ/VectorBox пишут промо обычными роликами
без перестановки.
