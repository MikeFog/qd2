# Сводный медиаплан по нескольким акциям

«График размещения по нескольким акциям» — печать одного медиаплана,
объединяющего выпуски нескольких рекламных акций так, как будто это одна
большая акция.

## Как выглядит для пользователя

Меню **Трафик → График размещения по нескольким акциям**. Открывается окно
с одним полем — номера акций через запятую. После ввода печатается медиаплан
в Excel: выпуски всех перечисленных акций сведены по агентствам и
радиостанциям, стоимость просуммирована.

- Заказчики всех акций перечисляются в шапке и в заголовке листа
  (`График размещения по нескольким акциям № 123, 456, 789`).
- Номера проверяются **не закрывая окно**: если хотя бы один не найден
  (не существует или акция удалена), выводится список ненайденных номеров,
  введённый текст остаётся на месте — пользователь правит и повторяет.
- Поддержан только базовый вариант: без «по месяцам», «за период»,
  «выборочно по роликам».

## Что затронуто

### SQL (`ArtvisDB/dbo/Stored Procedures`)

| Объект | Изменение |
|---|---|
| `MediaPlanRetrieve_v2` | новый параметр `@actionIDString` — набор акций через запятую с хвостовой запятой; фильтр рядом с существующим `@actionId`. Одиночные вызовы не затронуты. |
| `GetUniqueMMsForAction` | новый параметр `@actionIDString` — то же; `@actionID` стал необязательным. |
| `MultiActionMediaPlanActions` | **новая.** Возвращает строку на каждую существующую (`deleteDate IS NULL`) акцию из списка + её фирму. Форма ввода сверяет число строк с числом введённых номеров. |

Все три процедуры вызываются напрямую (`DataAccessor.LoadDataSet`), в
`iStoredProcedure` не регистрируются.

### C# (`Client`)

| Файл | Изменение |
|---|---|
| `Classes/MediaPlan.cs` | режим набора акций: `CreateInstance(IList<Action>, bool)`, ветки в `PrintActionInfo` / `LoadData` / `PrintFooter` / имя файла, перегрузки `PrintCaption` и `PrintHeader`. |
| `Forms/FrmMultiActionMediaPlan.cs` | **новая** форма ввода номеров (раскладка по образцу `PrintMediaPlanSettings`). Проверяет существование акций через `MultiActionMediaPlanActions` в `btnOk_Click`, форму не закрывает при ошибке. |
| `Forms/MDIForm.cs` | диспетчеризация `miMultiActionMediaPlan` → `ShowMultiActionMediaPlan()`: загрузка акций по валидному списку из формы, `MediaPlan`. |
| `Client.csproj` | регистрация новой формы. |

### Метаданные

`ArtvisDB/Scripts/multi-action-media-plan-seed.sql` — идемпотентный, добавляет
один пункт `iMenu` (`miMultiActionMediaPlan`, ветка «Трафик», позиция 55).
**Права (`GroupMenu`) не раздаются** — назначают администраторы вручную.

## Порядок развёртывания

1. Бэкап продуктивной базы.
2. Процедуры — один скрипт (`CREATE OR ALTER` ×3, изменения обратно совместимы):
   ```
   sqlcmd -S <сервер> -d <база> -E -f 65001 -I -i ArtvisDB\Scripts\multi-action-media-plan-procs-deploy.sql
   ```
   Он собран из канонических файлов
   `MultiActionMediaPlanActions.sql`, `GetUniqueMMsForAction.sql`,
   `MediaPlanRetrieve_v2.sql` — при их изменении пересобрать скрипт.
   Альтернатива: развернуть эти три файла по отдельности.
3. Скрипт метаданных:
   ```
   sqlcmd -S <сервер> -d <база> -E -f 65001 -I -i ArtvisDB\Scripts\multi-action-media-plan-seed.sql
   ```
4. Свежая сборка клиента (`Merlin.exe`).
5. Администратор выдаёт группам право на новый пункт меню.

## Проверка

- Один номер в списке → результат совпадает с обычным медиапланом акции
  (пакетная печать при подтверждении, вариант `Massmedias`).
- Несколько акций одной фирмы на одной радиостанции → выпуски в одной сетке,
  `quantity` роликов и стоимость просуммированы.
- Акции разных фирм → в шапке и заголовке все фирмы и все номера.
- Несуществующий/удалённый номер → форма остаётся открытой, список
  ненайденных номеров в сообщении, введённый текст сохранён.
