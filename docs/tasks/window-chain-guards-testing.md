# Запрет переноса объединённых окон в неправильный порядок — тестирование

Документ для тестировщика. Что и зачем — в `docs/window-merging.md` §3
(«Внесённые ограничения»). Проверяем **один** новый запрет в форме
**«Трафик» → «Трафик-менеджмент»**.

**Суть одной фразой:** объединённые (в интерфейсе — «Объединить со следующим»)
рекламные окна — это непрерывный кусок эфира из нескольких окон подряд, где одно
идёт раньше другого. Раньше объединённое окно можно было перенести по времени так,
что окна менялись местами, и выгрузка в эфир молча портилась. Теперь такой перенос
запрещён.

> В коде и в `docs/window-merging.md` та же вещь называется «цепочкой окон» /
> «склейкой» — это внутренний термин, тестировщику он не нужен.
>
> Запреты на изменение продолжительности объединённого окна и на объединение
> окон при уже настроенном «тарифе-продолжении» **пока не вводятся** — обсуждаются
> с заказчиком.

---

## 0. Что должно быть развёрнуто

1. **SQL-скрипт** `ArtvisDB/Scripts/window-chain-guards-deploy.sql` на той базе,
   к которой подключается тестовый клиент. Идемпотентный, повторный запуск
   безопасен. Меняет 2 процедуры (`TariffWindowMoveTime`, `TariffWindowIUD`) и
   обновляет 1 строку в `iMessage`. C# не трогали — свежая сборка не обязательна.
2. Тестируем на копии рабочей базы, **не на проде**.

Быстрая проверка, что скрипт применён:

```sql
SELECT name, [message] FROM iMessage WHERE name = 'LinkedWindowsWrongOrder';
-- 1 строка, текст про «объединённые окна»
```

Если скрипт не применён — вместо человеческого текста ошибки будет виден голый код
`LinkedWindowsWrongOrder`. Это тоже считается «запрет сработал», но текст нужно
поправить (доразвернуть скрипт).

---

## 1. Подготовка: объединить два окна

1. Открыть **«Трафик» → «Трафик-менеджмент»**.
2. Слева выбрать радиостанцию, у которой в текущей неделе есть рекламные окна.
3. В сетке найти день с **двумя соседними по времени окнами** (две заполненные
   ячейки в одной колонке-дне, одна под другой). Запомнить их время — дальше
   «окно A» (раннее) и «окно B» (позднее).
4. Правой кнопкой по ячейке **окна A** → **«Объединить со следующим»**.
   Подтвердить «Хотите объединить рекламные окна … и …?» → **Да**.
5. **Ожидаемо:** обе ячейки (A и B) стали **бледно-зелёными** — окна объединены.

> Если пунктов «Объединить…» в меню нет или они серые — окна не соседние,
> выберите другую пару.

---

## 2. Запрет: перенос времени, ломающий порядок окон

Время окна правится **двумя способами**, проверяем оба.

### 2.1. Перенос «через соседа» из сетки — запрещён

1. Правой кнопкой по **ячейке времени окна A** (левая колонка с временем в той же
   строке) → **«Отредактировать время выхода…»**.
2. В диалоге:
   - «Перенести на время» — поставить время **позже окна B** (например, если
     A = 10:00, B = 10:15, то ввести 10:30);
   - «Начиная с» и «Оканчивая» — **оба на текущий день** (сузить до одного дня,
     чтобы не задеть другие даты);
   - галки дней недели оставить как есть.
3. **ОК.**
4. **Ожидаемо:** операция **не выполнена**, сообщение:
   > Перенос не выполнен: после него объединённые рекламные окна вышли бы в эфир в
   > неправильном порядке — окно, которое должно идти позже, оказалось бы раньше…
5. Проверить: окно A осталось на прежнем времени, объединение (зелёные ячейки)
   цело.

### 2.2. То же с окна B назад — запрещён

1. Правой кнопкой по **ячейке времени окна B** → «Отредактировать время выхода…».
2. «Перенести на время» — **раньше окна A** (например 09:45). Даты — один день.
3. **ОК.**
4. **Ожидаемо:** тот же отказ `LinkedWindowsWrongOrder`.

### 2.3. Перенос, сохраняющий порядок — разрешён

1. Правой кнопкой по ячейке времени окна A → «Отредактировать время выхода…».
2. «Перенести на время» — **между A и B, но не позже B** (например, если
   A = 10:00, B = 10:15 → ввести 10:05). Даты — один день.
3. **ОК.**
4. **Ожидаемо:** перенос **выполнен**, ошибок нет. В сетке окно осталось в своей
   строке (грид на оригинальном времени), объединение цело.
5. **Вернуть обратно:** тем же диалогом перенести окно A на исходное время.

### 2.4. То же через паспорт окна («Свойства») — тоже запрещено

Это **второй путь** правки времени.

1. Правой кнопкой по **ячейке самого окна A** (не по колонке времени) →
   **«Свойства»**.
2. В поле **«Время выхода реальное»** поставить время **позже окна B**.
3. **ОК / Применить.**
4. **Ожидаемо:** отказ `LinkedWindowsWrongOrder`, окно не сдвинулось.
5. Повторить с окном B, поставив ему время **раньше окна A** — тот же отказ.
6. Контроль: через «Свойства» окна A поставить время **между A и B** (не позже B)
   → **сохраняется**.

### 2.5. Обычное (не объединённое) окно — без изменений в поведении

1. Правой кнопкой по ячейке времени **любого не-зелёного окна** →
   «Отредактировать время выхода…» → любое время → ОК.
2. Правой кнопкой по нему же → «Свойства» → поменять «Время выхода реальное» →
   ОК.
3. **Ожидаемо:** оба переноса выполняются как раньше, без ошибок.

### 2.6. Объединение и отмена объединения — работают как раньше

1. Объединить пару обычных окон (раздел 1), затем правой кнопкой по зелёной ячейке
   → **«Удалить объединение со следующим»**.
2. **Ожидаемо:** объединение создаётся и снимается без ошибок (проверка порядка
   срабатывает только на реальный перенос времени, а не на само объединение).

---

## 3. Уборка после теста

Отменить объединение, созданное в разделе 1:

1. Правой кнопкой по зелёной ячейке окна A → **«Удалить объединение со
   следующим»** → подтвердить.
2. Ячейки перестали быть зелёными.

Проверить, что время окна A вернулось к исходному (если меняли в разделе 2.3).
