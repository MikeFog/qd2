## 2. Как считается цена

### 2.1 Данные — `pc_GetStationsPriceModel(@MassmediaGroupID|NULL, @DateFrom, @DateTo, @userID|NULL)`

- **RS1** — строка на станцию; цены — `MAX` по сегментам **каждой колонки отдельно**; расчёт по ним не идёт, но они
  показываются в таблице и уходят в Excel (К-30). Станция без прайс-листа с тарифами в выдачу не попадает (молча).
- **RS2** — сегменты (прайс-лист ∩ период). Цена за секунду: тарифы в WD (будний флаг) и/или WE; `DENSE_RANK` по
  убыванию **различных** `Tariff.price`: прайм — 1-я цена, офф-прайм — 2-я; нет офф-прайма или 2-я = 0 → прайм
  (`NULLIF`, у 8 станций Переславля один платный уровень + 0 — так и надо сохранить); нет WE → WD. Третий и ниже
  уровни, цена окна и «Изменить цену» не участвуют; `isForModuleOnly` закомментирован — безвредно из-за `NULLIF`.
- **RS3** — периоды `UserDiscount` выбранного менеджера (`@userID`, с Deploy/53); до К.0 — всех пользователей, отбор
  на клиенте (К-17).

### 2.2 Формула (код после К.0)

WD/WE — выбранные будни/выходные, nWD/nWE — их число.

1. Количества строки: S = nWD × «Будни прайм» и т. д.; L = «Ролик (сек.)».
2. «Цена кампании» T = Σ по сегментам k: ((P_пВД·S_пВД + P_опВД·S_опВД)·|WD∩k|/nWD + (P_пВЫХ·S_пВЫХ + P_опВЫХ·S_опВЫХ)·|WE∩k|/nWE) × L × (1 + e/100), e — наценка прайс-листа за позицию строки (`extraChargeFirst/Second/LastRoller`). Доли дробные; T округляется до копеек (AwayFromZero) до передачи в SQL — до К.0 не округлялся, и `decimal(18,2)` отсекал 29 999,99… вниз (К-29).
3. «Объёмная скидка» c = `hlp_CompanyDiscountCalculate(станция, 1, первая выбранная дата, T)` — та же процедура, что в `ActionRecalculate`; вызов на каждую строку.
4. «Сезонный коэфф.» m: «одним числом» — значение поля; умолчание и минимум поля — `GetUserDiscount` = **MIN**(maxRatio) пересекающихся периодов, иначе 1; администратору — 1 (минимум 0). «Актуальный…» — цикл сегмент × период `UserDiscount`, W = Σ part × ratio_j; в колонке — W / Σ part; дни вне периодов — с коэффициентом 1 (до К.0 выпадали целиком, К-1).
5. «Цена до пакетной скидки» B = W × c.
6. «Пакетная скидка» k = `pc_PackageDiscountCalculateModel(«Период акции» с, 1, Σ T×c отмеченных, TVP(станция, L × выходы))` — логика `hlp_ActionDiscountCalculate`, кроме: калькулятор зовёт и при одной станции (система — при `@campaignCount > 1`), считает станции, а не кампании, только тип 1. С К.0 строки с 0 выходов исключены, как пустые кампании (К-5), дата — первый выбранный день, как у объёмной скидки (до К.0 — начало введённого периода).
7. «Итог» строки = B × k; «Итог:» — по отмеченным.

Итог **T × c × m × k** — так же, как система: `Campaign.price = tariffPrice × discount`, `finalPrice = managerDiscount × price × пакетная` (`ActionRecalculate.sql:416-417`).

### 2.3 Совпадение с настоящей ценой

**Правило системы для коэффициента** (`ActionRecalculate.sql:311-315`, `fn_GetMaxUserDiscount`): при первом пересчёте
кампании — MAX за период кампании **по тому, кто ставит** (`@loggedUserID`), а не по менеджеру акции; при разрыве
покрытия `UserDiscount` — max(MAX, 1) **на всю** кампанию; ниже MAX − 0,002 не пускает `fn_IsAcceptRatioForUser`
(`IssueIUD.sql:110`), освобождён только администратор; продлить кампанию в период с бо́льшим MAX нельзя
(`CannotChangeCampaignWithMaxDiscount`); грантор участвует только в `CampaignSetFinalPrice`.

### 4.1 Экран `/price-calculator`

- Вход: `ScreenRoutes` (`MenuRoutes.cs`) — `miPriceCalculator` → `/price-calculator`; `Access.CheckScreen`,

- Таблица станций — своя `.data-table` с правкой «Пр-ть ролика», «Позиция» и четырёх «Кол-во выходов …» по
  `@onchange`; строки с ручной правкой подсвечены; отметки переживают перечитывание модели (по станции); сортировка по
  щелчку на заголовке; цены — «2 или 4 колонки», диапазон «x – y», если по сегментам периода цены разные (К-30);
  предупреждение в строке «нет прайс-листа на N дн.» (К-3); плашка, если отмеченная станция выпала из модели при смене
  периода или группы; пустое состояние, если на период нет ни одной станции; подвал — «Итог:», выходы, хронометраж
  `[ч]:мм:сс`.
- «Сохранённые варианты»: карточки и кнопки как в десктопе; видимый признак «редактируется вариант …» и выход из
  режима; хранить и введённый период (для «Редактировать»), и фактический (для карточки и КП) (К-26).
- КП: агентства с заданным шаблоном; «Выбрать фирму» — `ObjectSelector` (образец `ActionNew.razor`) или без фирмы;
  «Создать КП» → `DocxPreview` → «Скачать Word»; без копии в серверную папку (выгрузки через браузер, 25.09.2026).
- Состояние — scoped `PriceCalculatorMemory` (параметры, правки, варианты) по образцу `ModuleRowsMemory`.

### 4.2 Ядро — движок вместо WinForms-сетки

Арифметику — в класс ядра почти дословно (правило «расчёты сохраняются один в один», прецедент `PlacementTemplate`);
скидки — одним вызовом SQL. Весь расчёт процедурой не делаем: переписывать дробное распределение на SQL — риск без
выигрыша.

- `Client/Classes/PriceCalculatorEngine.cs` (без WinForms и БД): `SelectDates`; модель `PcStation` (сегменты: даты,
  4 цены, 3 наценки), `PcRatioPeriod`, `PcRowInput`, `PcRowResult`; **один** цикл сегмент × период вместо двух копий
  (8a34ded пришлось вносить в обе); «одним числом» — частный случай; дни вне периодов `UserDiscount` — по 1 (К-1); **T округляется до копеек AwayFromZero до передачи
  в SQL** (К-29); дни вне сегментов считаются (К-3); `ApplyTemplate` (сейчас логика трижды); `Finish` — B, итоги,
  выходы, секунды, одна формула (К-20); правило колонок цен.
- `Client/Classes/PriceCalculatorData.cs` — фасад к БД: `LoadModel(group, from, to, userId)`, `Discounts(startDate,
  rows)` → `pc_CalcDiscountsModel`; коэффициент «одним числом» по умолчанию — MIN (`GetUserDiscount`, как десктоп), периоды —
  RS3 по выбранному менеджеру.
- Снимок варианта без DataGridView (`BuildSnapshot`, `RestoreRowDetails`; DTO уже в ядре); Excel — публичный
  сборщик на `OpenXmlExportDocument` (internal; дописать `SetColumnNumberFormat`/`SetAutoFitRows` или
  `SetFormatForCell`); КП — перегрузка `GenerateOneDoc(byte[] template, …) → byte[]`; публичные обёртки позиций и пути
  шаблона агентства (`Issue`, `Agency` — internal).

### 4.3 SQL (Deploy/53; контракты десктопа сохраняются)

1. `pc_GetStationsPriceModel`: `@userID int = NULL` (RS3 только по нему, NULL — как сейчас); `[name]` — `nvarchar` (К-17);
   цены RS1 оставить (диапазон считает движок по RS2).
2. `pc_PackageDiscountCalculateModel`: строки с `durationSec = 0` исключить, как `hlp_ActionDiscountCalculate` (К-5);
   второй ключ сортировки `TOP 1`, как в системе.
3. Новая `pc_CalcDiscountsModel(@startDate, @campaignTypeID = 1, @rows dbo.pc_CalcRow READONLY)` — курсор по строкам
   с `EXEC hlp_CompanyDiscountCalculate` (правило не дублируется) и пакет по отмеченным; пакет только при > 1 станции,
   как система; один вызов вместо N+1.

## 9. Вопросы владельцу и решения

**ВК-1. Правило сезонного коэффициента.** В калькуляторе два правила (MIN «одним числом» и средневзвешенное по
умолчанию с дефектом К-1), система — третье (§2.3: MAX по тому, кто ставит; при разрыве max(MAX, 1) на всю кампанию;
ниже не пустит). Расходятся они нечасто (MIN = MAX у 96,8 % кампаний 2026), но сильно — на стыках сезонов и года.
- (а) одно число по правилу системы (`fn_GetMaxUserDiscount` по первой и последней выбранной дате); поднимать можно,
  опускать нельзя; режим «по периодам» убрать в вебе и десктопе. Следствие: пока админы не заведут `UserDiscount` на
  2027, любой расчёт через Новый год даст 1,00; «Менеджер:» означает «кто будет размещать»; Ш3 перевести на то же
  правило (сейчас своя копия MIN, `FrmTemplate3.cs:259-265`);
- (б) оба режима, как в десктопе, с исправлением К-1 (дни вне периодов по 1) — на стыках всё равно не совпадёт с
  системой;
- (в) одно число по MIN, без режима «по периодам».

Рекомендация была: (а) — КП перестаёт обещать цену, которую не оформить; уходят К-1, RS3 и ~80 строк.

**Решение 17.10.2026: (б).** Оба режима остаются в вебе и десктопе; К-1 чинится — дни вне периодов `UserDiscount`
считаются по 1; «одним числом» по умолчанию — MIN, как сейчас; Ш3 не меняется (своя копия MIN остаётся до К.6, там —
через движок с тем же правилом). Расхождение с системой на стыках сезонов и года — известное.

**ВК-2. Объём правок десктопа.** По правилу десктоп меняем только по решению; К-1 с 01.01.2027 обнуляет расчёт по
умолчанию, К-29 уже сейчас даёт ступень хуже на пороге.

- (б) только срочное: К-1, К-25, К-28, К-29; движок — только для веба;
