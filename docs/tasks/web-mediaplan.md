# Медиаплан в вебе: план переноса

Черновик 2026-09-27, код не менялся. Справочник по десктопу — `docs/mediaplan.md`;
ссылки вида «§N» ниже ведут туда. В общем плане это этап 4
(`docs/tasks/web-migration.md`, «Отчёты и выгрузки», п. 2).

## 1. Отправная точка

- В вебе медиаплана нет: все `PrintMediaPlan*` в меню действий серые
  («В вебе пока нет»), пункты меню 181/182 ведут на `/todo`.
- `MediaPlan.cs` в ядро (`FogSoft.Core`) не входит: он пишет через COM Excel
  (`ExportManager`, `IDocumentSheet`) и сам показывает диалоги.
- Что уже есть в вебе и подходит:
  - `DocumentFormat.OpenXml` 3.4.1 в `FogSoft.Core`; образец общего
    (десктоп + веб) генератора — `Client/Classes/BroadcastGridDocx.cs`;
    образец xlsx — `FogSoft.Web/Infrastructure/GridExcelExport.cs`;
  - отдача файла в браузер — `js/download.js` (`DotNetStreamReference`) и
    `FileSaver` («Сохранить как»); решение Миши от 25.09: в вебе диалог
    браузера, никаких «папок из настроек»;
  - диалоги: `PeriodDialog` (период), `ObjectSelector` + `PickAsync`
    (выбор роликов, как `SelectionForm`), `DialogService`, `BusyService`;
    **выбора месяцев (аналога `FrmMonths`) нет**;
  - регистрация действий — `ObjectActions.ClassActions` (`Action`, `Campaign`, …).

## 2. Решения, которые нужны от Миши до начала

1. **Один пункт вместо 21.** Сейчас это 6 действий у акции, 6 у линейной
   кампании, по 3 у модульной/спонсорской/пакетной, 1 у акта, плюс кнопка и
   галочка в `ActionForm` и два пункта меню (§1.1). Все они различаются только
   тремя осями: раскладка, разбивка, выборочность. Предлагаю в вебе одно
   действие «График размещения…» у акции и у кампании, с одним диалогом:
   - разбивка: целиком / по месяцам / за период;
   - «только выбранные ролики» — галочка, по ней второй шаг со списком роликов;
   - три галочки из «Настроек печати» (подписи, предмет рекламы, скрыть тариф);
     «сразу сохранять на диск» не нужна.
   Старые имена действий в `iEntityAction` можно не трогать (веб зарегистрирует
   обработчик на одно имя, остальные скрыть), либо свести и в десктопе (п. 5).
2. **Какая раскладка у акции.** Действие «График размещения» акции печатает
   раскладку К (лист на кампанию), галочка в `ActionForm` — раскладку С
   (лист на агентство, блок на станцию). По логам 55 из 71 распечатки — С (§1.2).
   Варианты: (а) у акции только С, К остаётся у кампании; (б) у акции выбор
   раскладки в диалоге. Рекомендую (б) с С по умолчанию — дёшево, раз генератор
   общий.
3. **Разбивка и выборочность для раскладки С и сводного плана.** Сейчас их нет.
   SQL уже принимает период/месяц в режиме акции; для С нужно лишь отфильтровать
   станции без выпусков в периоде. Добавлять или оставить как есть?
4. **Переводить ли десктоп на новый генератор** (OpenXml вместо COM): файл
   сохраняется и открывается в Excel через `Process.Start`. Плюсы: один код
   на обе версии, нет зависаний `EXCEL.EXE`, быстрее на порядок. Минус: книга
   открывается уже сохранённой (сейчас — несохранённой «Книга1»). Рекомендую да.
5. **Ставка НДС** в итогах захардкожена текстом «(5%)». Оставить или брать из
   данных?
6. **Испанский.** Подписи медиаплана (заголовки, «Всего трансляций», дни недели)
   переводить через `iTranslation` по плану `docs/tasks/web-i18n.md` или пока
   только русский?

## 4. Целевая архитектура

```
FogSoft.Core (линкуется из Client/Classes, как BroadcastGridDocx)
  MediaPlanRequest   — источник (кампания | акция | набор акций), раскладка К/С,
                       разбивка (целиком | месяцы | период), ролики, настройки
  MediaPlanBuilder   — SQL → MediaPlanModel (без UI, без Excel)
  MediaPlanModel     — книга → листы → блоки: заголовок, шапка, ролики,
                       программы, таблица времени, сетка, счётчики, итоги
  MediaPlanXlsx      — MediaPlanModel → byte[] (.xlsx, OpenXml)

Client (десктоп)     — диалоги WinForms → Request → Xlsx → файл → Excel
FogSoft.Web          — диалог Blazor   → Request → Xlsx → download.js
```

Что должен уметь `MediaPlanXlsx` (всё, что сейчас делает `IDocumentSheet`):
несколько листов, Tahoma 8, жирный 12pt для заголовка, рамки у таблиц,
заливка `#D2D2D2` выходных, поворот текста 90°, форматы времени и денег,
ширина колонок (в OpenXml автоподбора нет — считать по длине текста), альбомная
ориентация, картинка подписи (`DrawingsPart`). Культура для дат, денег и дней
недели — явно `ru-RU` (в вебе у потока своей культуры нет).

## 6. Чек-лист приёмки веба

- [ ] Каждый вариант из §1.1 справочника доступен (или сознательно сведён по решению 2.1).
- [ ] Файл совпадает с десктопным по значениям ячеек на эталонном наборе.
- [ ] Имя файла: «График размещения для рекламной акции № N для {фирма}.xlsx» / «…по нескольким акциям № …».
- [ ] Подпись агентства вставляется по галочке; без картинки у агентства — без ошибки.
- [ ] Права: действия видны тем же группам, что в десктопе; сводный план — по правам пунктов 181/182.
- [ ] Выборочная печать: пустой выбор роликов — сообщение, а не пустой файл.
- [ ] Большой сводный план (4 акции, ~15 станций) строится за разумное время, с индикатором.
- [ ] Отмена на любом шаге диалога ничего не качает.

## 7. Риски

- **Визуальная точность.** Пользователи шлют файл клиенту; отличия в ширине
  колонок и переносах заметят. Лечится сравнением на эталонах (этап 3), до веба.
- **Картинка подписи в OpenXml** — самый громоздкий кусок рендера.
- **Производительность** — не узкое место: SQL уже вылечен (§8), OpenXml в
  памяти на порядки быстрее COM. Остаток N+1 (`GetPriceByPeriod` на кампанию ×
  станцию) терпим, кэшировать при необходимости.
- **Два поведения на время перехода**, если десктоп останется на COM
  (решение 2.4 = нет): любые правки медиаплана придётся делать дважды.
