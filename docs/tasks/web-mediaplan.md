# Медиаплан в вебе: план переноса

Черновик 2026-09-27, код не менялся. Справочник по десктопу — `docs/mediaplan.md`;
ссылки вида «§N» ниже ведут туда. В общем плане это этап 4
(`docs/tasks/web-migration.md`, «Отчёты и выгрузки», п. 2).

## 1. Отправная точка

- В вебе медиаплана нет: все `PrintMediaPlan*` в меню действий серые
  («В вебе пока нет»), пункты меню 181/182 ведут на `/todo`.
- `MediaPlan.cs` в ядро (`FogSoft.Core`) не входит: он пишет через COM Excel
  (`ExportManager`, `IDocumentSheet`) и сам показывает диалоги.
- Что уже есть в вебе и подходит:
  - `DocumentFormat.OpenXml` 3.4.1 в `FogSoft.Core`; образец общего
    (десктоп + веб) генератора — `Client/Classes/BroadcastGridDocx.cs`;
    образец xlsx — `FogSoft.Web/Infrastructure/GridExcelExport.cs`;
  - отдача файла в браузер — `js/download.js` (`DotNetStreamReference`) и
    `FileSaver` («Сохранить как»); решение Миши от 25.09: в вебе диалог
    браузера, никаких «папок из настроек»;
  - диалоги: `PeriodDialog` (период), `ObjectSelector` + `PickAsync`
    (выбор роликов, как `SelectionForm`), `DialogService`, `BusyService`;
    **выбора месяцев (аналога `FrmMonths`) нет**;
  - регистрация действий — `ObjectActions.ClassActions` (`Action`, `Campaign`, …).

## 2. Решения (обсуждение с Мишей 27.09.2026)

1. **Пункты — как в десктопе, не сводить.** Медиаплан печатают в контексте
   акции из дерева акций; все действия у акции и кампаний, у акта и на формах
   остаются отдельными пунктами. В вебе — по обработчику на каждое имя
   действия, диалоги те же (месяцы / период / ролики / «Настройки печати» без
   «сразу сохранять на диск»). Упрощение У-8 снято.
2. **Раскладка «по станциям» у акции — нового пункта не делаем.** Как в
   десктопе: пункты дерева акции печатают раскладку К, раскладку С даёт только
   галочка при OK в `ActionForm`. В вебе раскладка С одной акции появится
   вместе с переносом `ActionForm` (уникальный экран, отдельная задача);
   спешить не нужно, хотя это самый ходовой вариант (55 из 71 распечатки).
   Генератор раскладку С умеет уже сейчас — она нужна сводному плану.
3. **Разбивки для раскладки С и сводного плана — не добавлять.** Сводный план
   по нескольким акциям (пункты 181/182) — как есть, только целиком. Этап 6 снят.
4. **Десктоп переводим на новый генератор** (OpenXml вместо COM): один код на
   обе версии. Книга будет открываться уже сохранённой.
5. **Ставку НДС брать из данных.** Ставка лежит в `AgencyTax` (агентство, период,
   `divisor`), её уже считает `Agency.GetTaxValue(date)` для счёта и договора.
   В итогах блока — ставка агентства блока на **начало периода блока** (начало
   кампании, месяца или выбранного периода).
6. **Испанский — сразу.** Все подписи медиаплана (заголовки, шапка, «Ролики:»,
   «Программы:», итоги, дни недели, имена файла и листов) через `iTranslation` /
   `Tr.T` по `docs/tasks/web-i18n.md`; язык файла — язык пользователя.

## 4. Целевая архитектура

Сделано на этапе 2 (27.09.2026) — проще, чем задумывалось: отдельная модель
(`MediaPlanRequest` / `MediaPlanModel`) не понадобилась. Построитель пишет
через уже существующий, не завязанный на COM интерфейс `IExportDocument` /
`IDocumentSheet`, поэтому второй «рендер» — это просто вторая реализация
этого интерфейса.

```
FogSoft.Core (линкуется из Client/Classes и FogSoft.WinForm)
  MediaPlanBuilder   — SQL + раскладка листов → IExportDocument; GetRollers()
                       для выборочной печати, FileName, Settings, SelectedRollers
  IExportDocument / IDocumentSheet, SheetWriter — запись таблиц в лист

Client (десктоп)     MediaPlan — диалоги WinForms → MediaPlanBuilder →
                     ExcelDocument (COM, Excel запускается на первом листе) → файл/Excel
этап 3 (сделан)      OpenXmlExportDocument — IExportDocument на OpenXml (в ядре)
                     → byte[] .xlsx; десктоп: файл → открыть в Excel
FogSoft.Web (этап 4) диалог Blazor → MediaPlanBuilder → OpenXml → download.js
```

Что должна уметь OpenXml-реализация (всё, что медиаплан зовёт у `IDocumentSheet`):
несколько листов, Tahoma 8, жирный 12pt для заголовка, рамки у таблиц,
заливка `#D2D2D2` выходных, поворот текста 90°, форматы времени и денег,
ширина колонок (в OpenXml автоподбора нет — считать по длине текста), альбомная
ориентация, картинка подписи (`DrawingsPart`). Культура для дат, денег и дней
недели — явно `ru-RU` (в вебе у потока своей культуры нет).

### 5.1. Стенд сверки

`tools/mediaplan-compare/`: `MpHarness.exe` запускается из папки со сборкой qd2
(старой или новой), входит пользователем по ID без пароля
(`SecurityManager.GetUser`), строит 18 сценариев через `MediaPlan`/
`MediaPlanBuilder` рефлексией и сохраняет xlsx; `compare.py` (openpyxl) сверяет
две папки: значения, шрифты, заливки, рамки, поворот, форматы, ширины колонок,
ориентацию, число листов (`--loose` — для COM против OpenXml: рамки по видимым
граням, картинки по ячейке и размеру); `geometry.ps1` + `geometry.py` — видимые
ширины колонок и высоты строк в пунктах, как их показывает Excel (числа в файле
зависят от шрифта «Обычный»); `media.py` — картинки подписей. `--openxml` —
новая сборка пишет через OpenXml (сборки после этапа 3 — всегда), `--lang es` —
тексты через `Tr` на испанском. Как запускать — README там же.

Грабли OpenXml, найденные стендом: без `<sheetViews>` Excel масштабирует все
заданные высоты строк на 2/3; `<col>` без `width` Excel показывает нулевой
ширины; строки без явной высоты Excel подгоняет при открытии с учётом пустых
ячеек «Обычного» шрифта — поэтому высота пишется у каждой строки.

Эталонный набор для сравнения (составить на ArtvisDev): линейная, модульная,
спонсорская (с программами), пакетная кампании; акция с несколькими
агентствами (раскладка С); акция с переносами через границу месяца; сводный
план по 3–4 акциям; выборочная печать; кампания со скидкой и без.

## 6. Чек-лист приёмки веба

- [ ] Каждый вариант из §1.1 справочника доступен отдельным пунктом, как в десктопе.
- [ ] Файл совпадает с десктопным по значениям ячеек на эталонном наборе.
- [ ] Имя файла: «График размещения для рекламной акции № N для {фирма}.xlsx» / «…по нескольким акциям № …»; на испанском — переведённое.
- [ ] НДС в итогах — ставка агентства из `AgencyTax`, не «5%» текстом.
- [ ] Подпись агентства вставляется по галочке; без картинки у агентства — без ошибки.
- [ ] Права: действия видны тем же группам, что в десктопе; сводный план — по правам пунктов 181/182.
- [ ] Выборочная печать: пустой выбор роликов — сообщение, а не пустой файл.
- [ ] Большой сводный план (4 акции, ~15 станций) строится за разумное время, с индикатором.
- [ ] Отмена на любом шаге диалога ничего не качает.

## 7. Риски

- **Визуальная точность.** Пользователи шлют файл клиенту; отличия в ширине
  колонок и переносах заметят. Лечится сравнением на эталонах (этап 3), до веба.
- **Картинка подписи в OpenXml** — самый громоздкий кусок рендера.
- **Производительность** — не узкое место: SQL уже вылечен (§8), OpenXml в
  памяти на порядки быстрее COM. Остаток N+1 (`GetPriceByPeriod` на кампанию ×
  станцию) терпим, кэшировать при необходимости.
- **Десктоп на OpenXml** (решение 2.4) меняет привычку: книга открывается уже
  сохранённой (временный файл или диалог «Сохранить как» — решить на этапе 3).
